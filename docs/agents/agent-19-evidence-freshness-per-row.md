# agent-19：把闸门第 6 条改成「按行判过期」（消除"改一处全废"的假阳性）

> 项目根：`clover-project-cs16`
> 修的是**闸门自身的口径**：`tools/verify.ps1` 第 6 条 `evidence-freshness`。

## 0. 问题（skill 已明写这是错的）

当前实现：**把每条截图的 mtime 与"全工程最后一次代码改动"比较** ⇒ 只要改任何一个 `.cs`，
**全部** 截图当场变旧。

实测：`FAIL evidence-freshness 44/54 shots are OLDER than the last code edit (09-19 15:23)` ——
其中 44 张里绝大多数跟 15:23 那次改动（`ActorView.cs`，只影响角色外观）**毫无关系**（菜单 / HUD / 地图 / 尾盘图）。

skill 的原话（`SKILL.md` §1.11 第 6 条 / §1.12 第 3 条 / §1.13 第 6 条）：
> **作废范围 = 这次改动真能影响到的那几行**（同模块 / 同一功能链 / 同一屏），
> ⛔ **不是"工程里任何文件一变就全量作废"**；
> **把"受影响的行/屏"做成一份范围表……闸门第 6 条按同一份表判过期 ⇒ 规则与检查共用一个数据源。**

## 1. 只做这一件：改 `tools/verify.ps1` 第 6 条

**新口径（照此实现，别自己另发明）**：**逐行判过期** ——

1. 解析 `策划/验收表.md` 的验收行（A–E 段的数字键行，与第 12 条同一套行集合）；
2. 对每一行：
   - 取该行**引用的截图**（反引号里以 `.png` 结尾的名字，去重）；
   - 取该行**所述代码/资产**：反引号里的 `文件:行` 引用、类名（`XxxPanel` / `XxxModule` / `CsXxx`）或文件名（`*.cs`）——
     用"在 `client/Assets/Scripts` 与 `client/Assets/Editor` 里按文件名/类名找到的那个 `.cs`"作为它的实现文件；
   - **判据**：该行引用的**每张截图**的 mtime **必须 ≥** 该行所述实现文件的 mtime；
3. 汇总：全部满足 ⇒ `PASS`（报"N 行 / M 张图逐行比对通过"）；
   有违例 ⇒ `FAIL`，并**逐条列出**「行号 + 图名 + 图 mtime + 该行实现文件 + 其 mtime」；
4. **解析不到实现文件的行**（例如那行只写了行为描述）：按 `HUMAN-ONLY` 计，**不许当 FAIL**（防假阳性 —— skill §1.11 第 11 条）；
5. 没有任何截图的行 / 没有验收行可解析 ⇒ `HUMAN-ONLY`。

**硬要求**：

- 保持 **ASCII-only**（非 ASCII 用码点拼）、语法 0 错；
- 不许放宽第 12/15 条；不许把这条退化成"永远 PASS"（必须有真判据）；
- 注释里写清**为什么**改（引 skill §1.11 第 6 条原文那句"不是全量作废"）。

## 2. 改完必须做两次自检（skill §1.11 新增条款，缺一不可）

1. **已知正确样本必须 PASS**：当前工程跑一遍第 6 条 ⇒ 应以逐行口径 **PASS**（若仍有 FAIL，说明确实有某行的图比它自己的代码旧 —— 那就把它**如实列出**，并在回报里说明，⛔ 不许改口径掩盖）；
2. **已知错误样本必须 FAIL**：构造一个缺陷 ——
   挑一张**被某行引用的图**，把它的 mtime 改成**早于该行实现文件**（例如用 `Set-ItemProperty -Name LastWriteTime`），
   跑第 6 条应**抓出那一行**；自检完**把 mtime 还原**并核对。
