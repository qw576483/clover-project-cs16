# 约束与风险（clover-project-cs16）

## 引擎 / 平台固有约束（改不掉的，别硬碰）

| 约束 | 现象 | 结论 |
| --- | --- | --- |
| 引擎**没有第一人称相机** | `Game.Camera.Follow` 是锁 Z 的简单跟随 | FPS 相机业务自写（`Module/CameraRig/FirstPersonCamera.cs`） |
| 引擎**没有射线 API** | — | 命中判定用 Unity `Physics.Raycast`（业务自写） |
| `GameKey` 枚举**没有 `BackQuote`** | 控制台没法用 `~` 唤出 | 现用 `/` 或 `Num0`（验收表差异 #3；引擎补枚举后改回） |
| `AnimatorController` 只能 Editor 脚本生成 | 运行期建不出控制器 | 动画资产一律由 `Editor/Views/AnimSetup.cs` 产出并写进预制体 |
| 预制体**只能由 Editor 脚本生成** | ⛔ 不许手写 `.prefab` YAML | 改布局/坐标 = 改生成器 + **重跑生成器** |
| `Game.Anim.CreateAnimator` 的 `OnComplete` | **循环状态每次过 `normalizedTime≥1` 也会回调** | 只在有一次性动作（`_overrideState` 非空）时才响应 |
| `Game.Pool` 管"同一对象复用" | 不管"预制体 → 场景实例" | 角色/viewmodel 每次进图 `Instantiate` 是**合规的**（验收表差异 #9） |
| 引擎 `Game.LanBrowser` 单机扫不到主机 | 列表为空 | **真实行为**，不是降级（差异 #1） |

## 静默失败风险（不报错但结果错）

| 风险 | 现象 | 结论 |
| --- | --- | --- |
| **改了 UI 布局但没重跑生成器** | 运行期用序列化预制体里的旧坐标 ⇒ **只改代码看不到变化** | 改 `HudPanel` / `UiBuilder` 后**必须重跑 `Clover/CS16/生成游戏内面板`**（或走运行期重放兜底 `ApplyScoreBlock()`） |
| `CsPanelBase.Awake` 见有子节点就跳过 `BuildLayout` | 同上 | 同上 |
| 生成器**没跑过** | prefab / `.anim` / `.controller` 不存在 ⇒ 动画 `_anim == null`、模型不显示 | 首次拿工程必须先跑 4 个生成器（见 `registry.md`） |
| 离线编译通过 ≠ 运行正确 | `compile-check.ps1` 只验"签名存在 + 编译过" | 运行时行为必须进 Play 验（或实机截图） |
| `Resources` 路径大小写敏感 | 路径写错 = 资源静默缺失（只 Warn 一次） | 路径一律走常数（`CsViewTuning` / `CsHudTheme` / `CsUiStyle`），⛔ 不许散落字符串 |
| 截图证据可能比代码旧 | 旧的"已实测"截图为废证据 | 要查时看一眼图与被验源码的 mtime（`tools/verify.ps1` 的 `evidence-freshness` 是可选脚本，⛔ 不必跑） |
| `.ps1` 含 CJK 且无 BOM | PS 5.1 按 ANSI 解析 ⇒ **中文匹配静默失效**（脚本照跑、逻辑全错）；判据（`tools/verify.ps1:333/336`）= **无 BOM **且** `nonASCII > 0`** ⇒ ⚠️ **纯 ASCII 无需 BOM**（⛔ 别按"点名文件名"盲目补 BOM） | `.ai-tmp/**/*.ps1` 一律 **ASCII-only（首选）**；确需 CJK ⇒ **必带 BOM**。⚠️ **补 BOM 只治一次**（非 ASCII 字节仍在 ⇒ 将来任何"无 BOM 重存"会再触发）⇒ 首选把注释**改英文、`nonASCII` 清零**。实例：`stuckfix3-play.ps1` 收紧时加中文注释（`nonASCII=369`）触发 ANSI trap ⇒ 已裁改回 ASCII-only |
| **对账检查把生成物当手写实现** | 生成器产出（`Resources/**` 的 `prefab/anim/controller/asset/mat/unity/png/wav/bytes` 与每个 `.meta`）被逐文件判"没派活留痕" ⇒ **近 2000 条假阳性**，真违规被淹没 | `tools/verify.ps1` 第 15 条的对账**只统计人写的文本源码**（`Scripts`/`Editor`/`Resources` 三棵树都只取 `.cs`），生成物扩展名一律排除；`Scripts`/`Editor` 下的 `.cs` 必须继续逐文件对账（skill §1.11 第 11 条：**会误报的检查比没有检查更糟**） |
| **判据脚本用 `as UnityEngine.Object` 取业务类实例** | `CsMatch` 一类业务类是**普通 C# 类**（不继承 `UnityEngine.Object`）⇒ 转型恒 `null` ⇒ 该判据段**永远 SKIP**：脚本照跑、不报错，看上去只是"没数据" | 反射取到实例后**直接用**（`(CsMatch)field.GetValue(null)` 一类），⛔ 不许 `as UnityEngine.Object`；每段必须打"是否真跑过"的标记（如 `A-SECTION: ran items=N`），⛔ **SKIP 不许计入 PASS**（两个前例：`.ai-tmp/test/silentfix-judge.cs` A 段曾恒 SKIP；r1 release 判词把 SKIP 当 PASS，已追 NOTE 更正） |
| **片收工不关账（登记行仍读作"待办"）** | 实测三例：#141 买弹（menu 片已改未关）、#44 / #187 / #203 / #204（已做未关）、#159 开镜（`b443bf8` 2026-09-27 早已落地未关）⇒ 账本**虚高**（"还剩 48 条"实测约 35 条），后来者可能**重复劳动** | 每片收工**必须**把对应的 `策划/差异登记.tsv` 行改成终态（"已修" / "已实现（未提交）"）；片报告里必须有一行写明「本条登记行**已关 / 未关**」。**查某条是否其实已做**用三锚点：① `git diff HEAD` 里有没有目标文件的 diff；② `report-*.md` 里有没有同编号 / 同载体的**读数行**；③ 拿登记行"出处列"的原版载体去核对代码现状——⛔ 别只信"是什么 / 为什么"两列的文字 |
| **改上游数据格式不回归下游工具** | #11 把 `.cs16anim` 的命中/胶囊区从 6/7 改成 5 区，但**没跟上** `原版资源/cs16src/cs16_build.py` ⇒ 导出器被打挂（26/26 模型 rc=1），且**脚本照跑不报错**（错在结果里）| 改 `.cs16anim` / `.cs16mdl` / 任何生成链的**格式、区名、区数**时，**必须回归跑一遍下游导出器与相关生成入口**，并把回归读数写进报告（先例：修好后 26 个 `w_*.mdl` 重导出贴图 SHA 一致 59/0/0、`terror.mdl` 重生成逐位相同） |
| **按文件名 / 目录 / 被改写后的自证推"归属"** | 实测：`stuckfix3-play.ps1` 被两家各改过一次 ⇒ 按**文件名**推（"stuckfix3" ⇒ 以为属 `stuckfix`）**错**；按**改写后的自证**推**也错**（读到的是**改写者**的身份，于是把真正的主家判成"冒名"）。⇒ **"用别人的片名"之所以难自查：谁改写，谁就把自己的身份写了进去**。全仓曾据此**误报一次、又误撤一次** | 归属判定取「**未被他人改写时的**自证」，顺序：① `pre-edit` 快照 / 备份（最硬；⚠️ **必须读全** —— 默认 `-Named`、指向的探针 / 输出文件、header 的作者说明；**"裸 actor"可能是"从模板逐字复制"的残留**，实测据此**误判归属并误改文件一次**）→ ② 日志里**最早一次**运行行（`named=` / `actor=`）+ `named=` 的**前缀分布** → ③ 快照 / 备份**作者**与**归档 MANIFEST** → ④ **最后**才是"当前文件内自证"。⛔ 文件名 / 目录名 / 日志名 / "刚被别人改过的文件的自证" **一律不算独立证据**。⚠️ **"裸 actor"是最弱的单一证据** —— 它恰恰是**模板里最容易跟着复制过来**的字段（单看它会把"抄模板的残留"读成"作者身份"）。**另：证据与判据是两件事** —— **证据答"谁当初写的"，判据答"现在归谁维护"**（实测同一文件两层结论相反、各自都成立）。注：`-Actor` **格式闸**能拦"裸词"，⛔ **拦不住"格式正确但属于别片"的名字** |
| **静态自检全绿 ≠ 行为正确**（注释/声明落了、代码没落） | 实测：某补丁**只落了注释、漏了判断行**，而 `parse=0` + **反向替换逐位**校验**全绿通过** —— 最终是**行为探针**（同一账本形态下"改前 / 改后"对照）把它逮出来的（`post/RELEASE` 仍 = 1） | 凡改"**判定 / 闸门 / 开关**"类逻辑：① **必须跑行为对照**（至少"改前 / 改后"两格）；② 更稳的是**四格**（改前 / 改后 × **该变 / 不该变**）—— **既证"修好了"、也证"没修过头"**；③ **补丁脚本内置断言**"该行必须存在于文件"（防"注释落了、代码没落"再次无声通过） |
| **`UiBuilder` 生成器把活动场景换成空场景** | 该生成器会 `NewScene(EmptyScene, Single)` ⇒ **生成后不重开 Boot 就 Play** ⇒ **黑屏 + `Game.UI` / `Game.Event` 全 null**（实测：某片第一次 Play 读数**整轮作废**） | 跑任何 `UiBuilder` 系生成器后：**必须先重开 `Boot.unity` 再进 Play**；判据脚本**起手先断言** `Game.UI` / `Game.Event` 非 null（拿不到就**当场报错**，⛔ 别把 null 当"没数据"） |
| **"改动前"状态没留档 ⇒ 无法证明"只动了哪些"** | 实测：某**新文件（未入 git）**被修 1 处，**改前字节没单独归档** ⇒ 常规"反向替换 == 改前字节"**做不到**（没有改前字节可比） | 若改动是**可逆替换**：对**现文件做逆替换**重建改前字节 → 哈希 → 与**另一方的独立读数**（或日志 / sha 记录）**逐位交叉验证**；同时报"**行数 / 字节数差**"以佐证"差值全部出自该块"。前例：`blendfix-reverse-check.py`（重建值 `3DA2DB14…` 与另一 agent 的独立读数**逐位相同**）。⛔ **更好的做法仍是：动手前先归档改前字节**（这次靠逆替换补救） |
| **过滤 / 分类器的误判把真缺陷洗成"无害行"** | 实测两例：① 扫描器把"`-File $slot`（**走变量**，**正常形态**）"标成 `?`/`private`、归入"**不影响共享规则**"，**而那恰恰就是调共享件的调用点**（`buyfix` / `menu` / `menu2` 三处险些被漏）；② 判据脚本用 `as UnityEngine.Object` ⇒ 转型恒 `null` ⇒ 该段**永远 SKIP**，看着只是"没数据" | 凡"**分类 / 过滤 / 降级**"结果影响结论时：① 分类规则**要写进报告**，并用**反例验证**（至少一条"**应被判为受影响**"的样本真的命中）；② **保守档与确诊档分开记** —— 保守只是"**可能要查**"，**处置必须按确诊**；③ 注意"**工具 / 判定自身把真结论吃掉**"这一族（同族另两例：管道 `Select-Object -First N` **提前掐断子进程** ⇒ 假 `exit -1`；`as UnityEngine.Object` ⇒ 恒 SKIP）；④ ⚠️ **保守 / 激进两个缺省都会错** —— 实测同一扫描器 **v2 把"callee 不明"当无害 ⇒ 漏报** `animfix:298`、**v2.1 当受害 ⇒ 误报** `buyfix`/`menu`/`menu2` ⇒ **必须逐例解析真实 callee**（跟 dot-source 的模块、跟自实现的锁），⛔ 不许用缺省值 |
| **自检 / 演练与实物是两份逻辑（"测的是镜像"）** | 演练通过 ≠ 真实路径正确：演练若**复制一份判定逻辑**去测，实物那份仍可能是错的（改一处忘另一处）⇒ **假验证** | 自检 / 负控**必须调用真实路径上的同一函数**。前例：`botflip2` 的收工 `finally` 与演练**共用同一个 `IsMine($lockPath)`**（原 `-match 'stuckfix'` 会在自己**没上槽**时**替别人收工**：停他编辑器 + 释放他锁）；`throwfix2` 用 `LockOwner()` / `Owns-Lock()` 同一对 |
| **Play 驱动两坑（各片各写驱动 ⇒ 重复踩）** | ① side file 用 `File.Delete` 重建 ⇒ **上一轮原文被静默覆盖**（实测：#179b 的运行覆盖了 #179 的 120 s pre-fix 原文）；② 收工流程**锁已删、编辑器还留在 Play**（`$ErrorActionPreference=Continue` 下 `editor_stop` 静默跳过）⇒ 后来者接手看到"在 Play、无锁"，已造成一次误判与一段无锁会话 | 驱动必须：① 每轮 side file **先 Move 归档**（`<name>.<yyyyMMdd-HHmmss-fff>.bak`，**毫秒**级 + 留最近 N 个），⛔ 不许直接 Delete；② 收工顺序 **`editor_stop` → `open_scene(Boot)` → `RELEASE`**，三步各自 try/catch **互不阻断**，`RELEASE` 后**复查 `playMode` 仍为 playing 就再停一次**。参考实现：`.ai-tmp/drivers/botflip-probe.cs` 的 `ArchiveSideFile` + `botflip-play.ps1` 的 `Teardown`（含 `-DrillTeardown` 演练入口） |
