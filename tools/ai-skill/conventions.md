## 共享文本文件的写入口径（硬）

**多个片共用**的文本文件（`策划/差异登记.tsv`、`.ai-tmp/test/ledger.tsv`、`play-log.tsv` 一类）的**口径** = **无 BOM + LF（`\n`）**。

✅ **归一已执行**（2026-10-13/14，主 agent 发令；三张共享表现为纯 LF）⇒ **从此所有写入一律 LF**，写回时 ⛔ 不许再把 CRLF 带回来（两条坑见下表）。`.ai-tmp/**` 的临时产物**不强制**。

⚠️ **残留待收尾统一抹平**（有片在跑时不动）：`ledger.tsv` 1 行、`gate-selftest-window.tsv`（146）、`stuckfix3-probey.tsv`（1）—— 清单与命令见 `.ai-tmp/test/CLOSEOUT-main.md`。

**时间戳必须"读来的"，不是"想来的"（硬）**：一律取 `Get-Date` / 文件 `mtime`（先跑命令、再抄输出），⛔ 不许凭印象填。实测事故（2026-10-14）：某片批量补记 8 行台账时凭印象写时间，**出现"未来时间"**（写 `03:35/04:05/04:12/04:25` 而真实时刻才 `03:21`）**且在一张 append-only 表里顺序颠倒** ⇒ **任何"时间窗判据"读这段都会误判**。
**更正历史记录的姿势 = 追加一条「更正行」**（真实值 + 根因 + 影响面），⛔ **不回改历史行** —— append-only 的价值在**不可篡改**。
**⚠️ 判"谁先谁后"只看「文件内位置」，⛔ 不用手写行的"时间戳"（2026-10-14 实测）**：相邻两行里，上面那行写 `03:55`，而本机 PS 与 python 一致给出 `03:45:27`（**快了约 10 分钟**，且"更晚的时间戳、更早的写入"）。⇒ 这是"时间戳必须读来的"的**更进一步**：**即使读对了钟，"人写"的时间戳也不能当判据**。⇒ **不受影响**：`take-slot.ps1` **自己写**的 `OCCUPY`/`RELEASE` 行（同一工具、同一时钟）。
**`mtime` 只能证明"最后一次是谁写的"**，⛔ **不能证明"这个文件都是谁写的"**：接力改同一文件时后写者会覆盖前者（实测：两片都报同一文件的同一 mtime）⇒ 归属要看**各自自述 + 内容 sha 链**。

**写有价值的文本产物：安全模式（硬）**：**先 `encode('utf-8')` 校验 → 写 `.tmp` → 旧存 `.bak` → 原子替换**；⛔ **禁止直接 `open(path,'w')`**。实测事故（2026-10-14）：`open('w')` **先截断**，随后因字符串含**孤代理字符**抛 `UnicodeEncodeError` ⇒ **目标文件此刻已是 0 字节**，且**全仓无副本** ⇒ **1223 行里约 900 行永久丢失**（报告只能"部分原文重现 + 保留标题索引 + 以台账摘要兜底"，并**处处标'重建'**）。

**改共享表的唯一安全原语 = "行内定点替换"（硬）**：在**读到的该行**内做**字符串替换**，行外字节逐位不变；⛔ **不许"整行用一份常量重写"**。
⚠️ 为什么（实测 2026-10-14）：整行重写**看起来满足"只改命中行"**（它确实只写那一行），但**只要别人同期把该行改长/改短，就会静默回退他** —— 实例：`480520 → 478489 B`，**回退 2031 B、抹掉另一个片写进该行的 sha**（发现信号 = **字节数变小 + 预期 token 缺失**；处置 = 用改前备份**逐字节还原**，**sha 与字节双项相符才落盘**）。
⇒ **自检要升级**：① 改前后**非命中行逐位相同**；② **同行内非目标子串逐位相同**；③ 编辑脚本必须带 **REFUSE 闸门**（目标子串不存在、或出现次数 ≠ 预期 ⇒ **拒绝**）。
⇒ **"读最新 → 只改命中行 → 写回"这句话不够** —— 必须写明"**行内定点替换**"。

**⚠️ 归档"活文件"快照与源 sha 不一致 = 正常（硬，2026-10-14）**：`ledger.tsv` / `play-log.tsv` / `差异登记.tsv` **全队仍在追加** ⇒ 归档只冻结"**复制那一刻**"的快照 ⇒ ⛔ **别把 sha mismatch 判成"被改过 / 损坏"**；**MANIFEST 的 sha 只对"归档副本"负责**，与活文件比对**只在同一时刻才有意义**。

**⚠️ 存在性判定要有第二种方法互证（硬）**：实测某片用 `Join-Path` + `Test-Path -LiteralPath` 逐件判存在 ⇒ **7 件全部"静默假报 MISSING"**（改用 `Get-ChildItem -LiteralPath <目录> | Where Name -like` 才真相大白）⇒ **凡"XX 不存在"的结论，必须换一种方式复核**（与既有"PowerShell 存在性验证静默假结论"同族）。

**⚠️ 字节级自检必须扫 `NUL` 与 `BOM`（硬，2026-10-14）**：**只数"非 ASCII 字符（>127）"抓不到两类问题** —— **UTF-16 的 `0x00`** 与 **UTF-8 的 BOM（`EF BB BF`）**。⇒ **"改完自检"里并入 `NUL` / `BOM` 扫描**（一条命令、零成本）。⚠️ 附带后果（实测盘点：2414 件里 189 件非朴素 UTF-8）：**若用"按 UTF-8 读的 grep"去扫这些文件，会得到"假 0 命中"（看起来没内容）** ⇒ 读它们须 `-Encoding Unicode` / `utf-8-sig`。

**⚠️ 取证落盘的编码（硬，2026-10-14 全队自查）**：⛔ **别用** ① **`>`**（PS 5.1 默认写 **UTF-16LE + BOM**，首 4 字节 `FF FE`）② **`Tee-Object -FilePath`**（同 = Unicode）③ **`Out-File` / `Set-Content -Encoding utf8`**（写 **UTF-8 带 BOM**）。⇒ 用 PS 读多数正常，但 **utf-8 工具 / python / grep 会报错或乱码** ⇒ **别误判成"文件损坏"**（实测命中：3 片各 4–5 件 UTF-16、2 片各 2 件 UTF-8+BOM）。⇒ 统一改 **`[IO.File]::WriteAllText(..., UTF8 无 BOM)`** 或 python **`open(p,'w',newline='')`**。
　✅ **例外（安全）**：**`cmd /c "... > file"`** ⇒ cmd 重定向写**原始 stdout 字节**、**不经过 PS 编码**（实测无 BOM/非 UTF-16）。
　📌 **已采集证据的处置标准**：⛔ **不重编码**（采集即冻结，避免"字节被改过"的争议）⇒ **归档加 `ENCODING-NOTE.txt`**（逐文件编码 + **正确读法**：PS `-Encoding Unicode` / python `encoding="utf-16"`；**grep 报 binary = 编码，不是损坏**）+ **MANIFEST 增 `encoding` 列**（`UTF-8-noBOM` / `UTF-16LE-BOM`）。

**程序集新鲜度必须「按来源配对」比较（硬，2026-10-14 实测）**：闸门当前用**全树最新 `.cs`** 去比**每一个 dll** ⇒ **Editor-only 改动会把运行时 dll 拖黑** ⇒ `stale` **恒成立且自我不可愈**（重建 Editor 侧**不碰** `Cs16.dll`）⇒ **全队取槽永拒**（实测：`Cs16.dll 03:40:01` < `AnimSetup.cs 03:45:56`，而它比自己来源 `03:27:38` **更新**）。⇒ **正确口径 = 每个 dll 只与自己的来源树比**：`Cs16.dll` ↔ `Assets/Scripts/**`（`Cs16.asmdef` 所在）；`Assembly-CSharp-Editor.dll` ↔ `Assets/**` 里的 Editor 文件夹。⚠️ **两个同族坑**：① 把 Editor 源塞进 `Cs16.dll` 的比较 = **假 stale**；② 本项目**没有 `Cs16.Editor.dll`** ⇒ 等它 = **永久 never**。⚠️ **映射不到来源的 `.cs`**（如将来 `Assets/Plugins/**` ⇒ `Assembly-CSharp-firstpass`）⇒ **只警告、⛔ 不判 `stale`**（否则又是一个"改完永远取不到槽"的恒拒）。⇒ 修好后"**改 Editor 脚本 ⇒ 立刻可放行**"，无需任何手动 `recompile`。
　⚠️ **实现注意**：来源映射**按 asmdef 目录树派生**（⛔ 不硬编码 `Scripts`）；**来源集合为空 或 映射不到** ⇒ **跳过 / 只警告**，⛔ **不判 `never`/`stale`**（这条错法已栽过一次）。

**持锁心跳 = 契约的另一半（硬，2026-10-14）**：`take-slot` 契约要求 holder **`-Touch` 心跳**（刷新 `play.lock` mtime）⇒ 实测有驱动**只做 take/Release、不做心跳** ⇒ 长链跑 Play 时锁 mtime 不刷新 ⇒ 别人把"**活跃**"误判成"**已死**"。⇒ **各驱动自查"我做心跳了吗"**（正确写法：每次 unity 调用前、**仅 `Owns-Lock` 时** 跑 `take-slot.ps1 -Actor $Actor -Touch`）。**判"持有者是否还活着"并列三条信号** = `play.lock` mtime（持有者在动）+ `play-driver-log.tsv`（驱动心跳）+ **`client/Logs/Editor.log` mtime**（Unity 持续写 ⇒ 判"编辑器有没有死"）⇒ **三者同时静默**才谈"可能已死"。

**路径必须来自「真源」，⛔ 不许猜（硬，2026-10-14 主 agent 亲裁实测）**：实测事故 —— **主 agent** 查锁时**自拼路径** `.ai-tmp\play.lock`（真路径 = **`.ai-tmp/test/play.lock`**，脚本锚在 `$PSScriptRoot`）⇒ `Test-Path=False` ⇒ **假 ABSENT** ⇒ **错误读数已广播全队**（与今晚 7 件"假 MISSING"**同族**）。⇒ 规矩：**① 路径取工具自报**（`take-slot.ps1 -Probe` 这类入口**自己知道路径**）；**② 报"文件不存在 / 锁已空"这类结论前先三法互证**（`Test-Path -LiteralPath` + `[IO.File]::Exists` + 目录枚举）；**③ 报了错读数 ⇒ 立刻自查 + 更正广播**（不静默改口）。

**跨层引用三问（硬，2026-10-14 实测）**：引用任何字段 / 字段名 / 机制之前，必须能回答 —— **① 这是哪一层的证据 ② 到目标层经过谁的投影 ③ 投影我核过没有**。实测事故：**包源码 `CommandExecutionResponse.cs` 里的 `status` / `retryable` / `busyReason` 是"包层 HTTP 503"那套，而 `take-slot.ps1` 只走 CLI** ⇒ 若按包层字段名去解析 CLI 输出 ⇒ **永不匹配 ⇒ fail-closed ⇒ 新恒拒**。⇒ 同族错误：拿 `mtime` 断言"谁写的"（归属错）、拿"某个层级"的证据去断言"另一层级"的行为 ⇒ **跨层引用必须写明投影路径与核验状态**。

**"③ 无人在写码"的可复算判据 = 窗口内 `*.cs` 热件数（硬，2026-10-14 定案）**：`Get-ChildItem -LiteralPath <client/Assets> -Recurse -File | Where-Object { $_.Name -like '*.cs' -and $_.LastWriteTime -gt (Get-Date).AddMinutes(-15) }` ⇒ **输出为空 ⇒ 无人在写码**；有输出 ⇒ **逐条即"谁的在制品"**（抄进台账那句）。⚠️ ⛔ **别用"热文件总数"**：实测它会给 **4999**（**全是 `.asset`/`.meta` 的导入尾流**，而 `.cs` 热件 = **0**）⇒ 会把正常排队的人**吓退**（假阳性），而真正要防的是**代码**在制品。
**`-Probe` 会问一次 `editor_status`（硬，2026-10-14 按实码更正 ×2）**：它**只读、不需持槽、⛔ 不调 `recompile`（不触发编译）**，**但会调一次 `editor_status`**（`:555 → Editor-Gate :192 → :220 unity command editor_status --timeout 120`）⇒ 判"`gate 2.6`"那部分在 `-Probe` 下**是 mtime 代理**（不触发编译），但**整个 `-Probe` 会问一次通道**。
⚠️ **"慢不慢"取决于「通道有没有在干重活」（导入 / 编译 / 域重载）** —— ⛔ **不能由"有人在 Play"推出"会慢"**：实测（04:18:40，**正有人 Play 的同时**）`editor_status` **`rc=0` / 秒级返回**；而同一通道在**导入风暴**期间（04:00–04:02）**确实超时 120 s**。⇒ 两句都要记住：**"有人在 Play" 与 "通道慢" 互相独立**；**判"通道卡死"只认"真的没回"**（超时封套 / `data:null`）✓ ⛔ 别传"有人在 Play ⇒ 探针会慢"（那会让人在**秒回**时也以为"闸门卡住"，与本条想防的误判是同一个坑的另一侧）。
**驱动"收工动作"必须与"我是否真的驱动过编辑器"绑定（硬，2026-10-14 实测）**：实测危险路径 —— 某驱动的 preflight 写成"`playMode != stopped` ⇒ 跑 `editor_stop`" ⇒ 在"**取锁到动作之间可能有人进 Play**"的情形下，这会**停掉别人的会话、毁掉其取证**。⇒ **硬做法**：preflight **只复读一次、非 `stopped` 即 `throw`（fail-closed）、⛔ 绝不调 `editor_stop`**；并用 `$droveEditor` 标志（**只有真的发出 `editor_play` 才置 true**）分流收工：**没驱动过 ⇒ 只释放锁、编辑器原样不动**；驱动过 ⇒ 才走 `release → editor_stop → open-boot` ✓

**清陈旧锁的"第 0 步"= 直接问持有者；异步答复期保持冻结（硬，2026-10-14 定案）**：⛔ **不得把"没回话"当成"不在跑"**（实测：持有者可能正卡在一次 **~11 分钟**的生成器调用里、对外看像 stalled，而它其实是活的）；⇒ 只有在**四条件 AND**（租期 / 心跳 / 编辑活动 / **全仓最近 N 分钟被改的文件**）**全真 + 第 0 步问过且无相反证据**时，才允许清锁 + 留痕。
**"空输出"必须能自证（硬，2026-10-14）**：任何"0 命中 / 无人在写码"的**空输出**，必须一并打印 **`as-of 时刻 + 根路径 + 检索实现（第二实现）`** —— 否则**无法区分"真空"与"检索器坏了"**（今晚已多次出现"假空/假 MISSING/假 ABSENT"）。

**⛔ 禁止"绕过锁"直接驱动编辑器（硬，2026-10-14）**：原子建锁只挡"抢锁"，**挡不住绕过去直接 `editor_play`** ⇒ 会**毁掉正在持锁那片的整轮取证**（实测情形：#220 ③.2 正在跑时，别人若绕过锁进 Play 即毁）。⇒ **一律先取锁、再 `editor_play`**；**锁状态只认"当场 `-Probe` 那一行"**（⛔ 不用"某人某刻的读数"当队列放行依据 —— 实测出现过"清锁 → 又被人取走"的时序漂移）。

**`git` 查改动：中文路径必须 `-c core.quotepath=false`（硬，2026-10-14 实测）**：默认 `core.quotepath=true` ⇒ **非 ASCII 路径被转义成八进制**（`"\347\255\226\345\210\222/…"`）⇒ **按中文关键词 grep `git status` 必然 0 命中** ⇒ **会漏看自己/别人的中文路径改动**（如 `策划/差异登记.tsv` 就在待提交集合里）。⇒ 列清单固定用 `git -c core.quotepath=false --no-pager status --porcelain`（或 `-z`）。
**`Copy-Item` 三坑（硬，2026-10-14 两片各自实测）**：**① `-LiteralPath` 不展开通配符** —— 写 `-LiteralPath "$src\*"` ⇒ **一件都不复制、且无报错**；**② 目标已存在时 `-Destination <目录>` 会把源目录「整体嵌入」**（结果 `dst\src\…`）、无报错，**顶层还是旧版**（有人靠**逐件 sha** 才发现）；**③ 正确写法** = `Copy-Item -Path "$src\*" -Destination $dst -Recurse -Force`（或先删目标）**＋ 逐件 sha 互证**。⇒ **"复制/写入成功"的断言 = 件数（必要条件）+ 至少一个内容哈希（或整目录摘要）**。
**"读目录内容"必须带 as-of 时刻，且目标可能正被他人写（硬，2026-10-14 两片更正实测）**：实测 —— 有人读到某目标目录"**0 件**"，被记成"假读数/方法错"，**两片复核后更正为「在途读」**（目标 `Creation=04:28:36`、`LastWrite=04:29:10`，第三方正在"建目录 → 填文件"，读数落在窗口内）。⇒ ⇒ **教训 = 读目录/文件内容必须带 as-of，并假定目标可能正在被写**；⚠️ **⛔ 别把它归成"换第二种实现就能避免"** —— 那一二十秒里**两种实现都会给 0**（与"活文件快照天然与源不一致""相隔十几秒的两次读数被当同一时刻"同族）。
**"表读数可比"的最小充分集 = 四元组（硬，2026-10-14 定案）**：**`副本路径 + bytes + sha256 + 关键计数（如 uniq/max）`** —— 缺任一项，两次读数**不可比**。实测反例：`196/223` 与 `198/225` 都能在盘上复现，但 `195/222` 在**任何副本、任何 id 定义下都复现不出来** ⇒ ⇒ **结论不是"定义不同"而是"文件状态/时刻不同"**（**5 副本 × 3 定义变体**复算得出）⇒ 凡引用旧读数，必须给四元组；给不出 ⇒ **标"不可复核"**。
**PS 落盘 / 传参三坑（硬，2026-10-14 实测）**：**① `WriteAllLines($p, @(...), $enc)` 会把数组"压成一行"**（有人因此废掉 2 轮 Play）；**② 数组字面量里 `'a' + $v` 会被逗号拆开**（结果多张图**全落同一个文件名**）；**③ `--args '["local"]'` 传到不了探针**（改**读 spec 文件**这类无歧义通道）。⇒ 落盘一律 `[IO.File]::WriteAllText` / `AppendAllText`（显式 `UTF8Encoding($false)`），传参优先"文件"而非"命令行字符串"。
**"写 / 复制 / 收工"类动作必须带「阴阳性对照或负控格」（硬，2026-10-14 定案）**：⛔ **静态声明不算**。**⚠️ 且负控常能抓出真缺陷 —— 三个实证**：① 无锁时跑某驱动 ⇒ 它**在"所有权守卫之前"就 `Remove-Item` 自己的输出** ⇒ **一次误跑会先删掉上一次的冻结证据**（已把删除移到守卫之后）⇒ 定案：**守卫/闸门之前⛔不许有任何破坏性动作**；② 把 `finally` 的**真实字节**抽出来、用桩以 `droveEditor=false/true` 各执行一次 ⇒ **"`false` ⇒ 一次编辑器调用都不发"由静态声明变成实测**（且第一次桩漏了被引用的变量 ⇒ 报错 ⇒ **反证对照真的在执行那段代码**）；③ 取一件把它**在正中翻 1 字节** ⇒ 要求"报 DIFF 且首异位 = 4304"、同件自比要求 `ok` ⇒ `CONTROL RESULT = PASS` ⇒ **对照组能失败才可信**。
**EOL 归一前必须"先灭注入源"（硬，2026-10-14 实测）**：实测 —— 在准备把几张共享表统一成 LF 时，只读扫描发现**仍在用的驱动还在往这些表写 CRLF**（两支共享驱动、共 5 处 `\r\n`，其中一处是"陈旧锁回收"的 NOTE 行）⇒ ⇒ **"改一处、别处继续注入"= 归一等于白做**。⇒ 顺序：**① 先修"会写该表"的所有在役驱动的终止符 → ② 再跑归一**；**退役/旧脚本只在清单里列名，⛔ 不改不删**。⚠️ 同族：**改共享件前先"自证除该处外逐位不变"**（前后对比法），并**声明"未实跑"**（⛔ 不为形式主义占槽）。
**"检测器"必须先用"已知阳性"验一次，否则 0 命中不可信（硬，2026-10-14 自曝实测）**：实测 —— 有人写"两行黏成一行"的检测器时把正则锚在行首 ⇒ **恒 0 命中**；它自述"**若我没复核就用它，会报'黏行已修'**"（而缺陷仍在）。⇒ 规矩：**凡"找缺陷"的扫描器，先用"已知存在的那个实例"跑一次，必须命中**；命中不了 ⇒ **先怀疑检测器**（与"双实现 + 阳性对照"同族）。
**交付物演进要"按指纹留档"，⛔ 不要原地改名覆盖（硬，2026-10-14 自曝实测）**：实测 —— 某驱动修了两次，中间态 `8A164F2E…` 被**原地覆盖** ⇒ 现盘 **0 命中** ⇒ **第三方无法复核那一步**（闭链只能靠外部实测的 `26/5` 与累计 `29/6` 之差倒推）。⇒ 正解：**每一版都按"新 sha 后缀"留档**（如 `x.ps1.post-EC92213F`），⛔ 不用同一个名字反复覆盖。

**"时长 / 件数 / 像不像"都不是完成判据（硬，2026-10-14 实测的假阳性家族）**：实测 —— 有人按"**只跑了 13 秒，不像跑完**"推断另一片没跑成 ⇒ **撤回**：对方的判据是**纯计算（不进 Play）**且那次"重新编译"是 `up_to_date`（**不编译**）⇒ 十几秒完全合理；**正确判据 = 落盘 verdict + `diagnostics: []`**。⇒ 同族三条：**"有写入 ≠ 持有者活着"**、**"无心跳 ≠ 已死"**、**"时长短 ≠ 没跑完"** ⇒ ⇒ **一切"像/不像"的推断都要换成"盘上产物里的判据"**。
**凡交付"可复检"的判据，必须问：入口与最小材料各在哪、提交后还在不在库（硬，2026-10-14 实测）**：实测 —— 某片的**一键复检入口全在 gitignored 区**（驱动 `.ps1/.cs` + 判据脚本 + 报告）⇒ 按"临时区不提交"的清单 ⇒ **结果是"产品码在库、判据与执行器不在库"** ⇒ 后人**只能从零重建**。⇒ 规矩：**判据/执行器要入库**（如 `tools/probes/`，与同族件放一起）；移植时**同步改内部路径引用** + **干跑证明仍可执行** + 在报告列"**复检所需最小材料清单**"（⛔ 否则入口在库、**材料不在库**，仍跑不起来）。（同族：提交清单里"**运行时资产**"也常被当"生成物"过滤掉而漏项。）
**"我发了"≠"它收到了"（硬，2026-10-14 实测）**：实测 —— 一条消息的工具返回 **`No result found`**（投递失败），而发送方**以为对方已收到**；若按"它已收到"去安排后续，就会出现"**两边都在等对方**"。⇒ 规矩：**关键交接消息要带"回执式"确认**（或把关键数据同时写进盘上的共享件），并**把"投递失败"当一等故障上报**。

**"某成员是否已终止"⛔ 不能只看框架通知（硬，2026-10-14 实测：它**反向假阳性**）**：实测 —— 框架报某成员"**会话错误终止**"，而该成员**仍在待命、仍在产出**（它当场**追加了一行带戳台账**作为"我此刻活着"的盘上证据，并实时复读归档根与我实测**逐位吻合**）；同批通知里**真终止与假阳性混杂**（今晚 4 例误报/需分辨 + 2 例假阳性）⇒ ⇒ **判据 = "看它还在不在产出新产物 / 还回不回话"**（**产物带戳 > 通知**）；⛔ 别据通知就宣布"某片已下线"、更别据此跳过它还能做的那一步。
**阴性对照必须写成"正确实现也满足不了它"（硬，2026-10-14 自曝实测）**：实测 —— 某人的**阴性对照第一版是空对照**：它的正则把"**正确实现的那一行**"也命中了，却报 `NEG = 0` ⇒ 那个对照**等于没做**（且已在台账里留下不实的一句，后以 CORRECTION 行更正）。⇒ 规矩：**阴性判据必须能区分"实现正确"与"实现错误"**；写完用它跑一次**正确版本**，**必须不命中**，否则判据本身不成立。
**引用"行号"要带 as-of，并给"byte + 行首指纹"（硬，2026-10-14 实测）**：实测 —— 同一处缺陷被两个来源分别记成"行 462"与"行 474"⇒ 争不出结论。⇒ 规矩：**① 报告引用只用"内容判据"（唯一权威 = 行首/行尾指纹 + 结构判据）；`byte offset` 与`行号`都只作参考** —— ⚠️ **两条精确边界（实测，⛔ 别传成"offset 会自己漂"）**：**① 只在尾部追加的表 ⇒ 前置行的 `byte offset` 与行号都不漂**（实测表从 `356219 → 361812`、**+5,593 B**，两处仍 `324943` / `351195`；行号也仍 462）；**② 会漂的是「行内补/删换行」之后的部分** —— 其后所有行的 **offset 与行号整体位移**（且 CR 修掉后，其后行号整体 −1）⇒ **这才是"报告优先用内容判据"的真理由** ✓ **③ ⚠️ 报 offset 必须写清"字符下标 / 字节偏移"并给计算式** —— 本批**两片独立**犯同一错（**用解码后的字符串做 `find(chr(13))` ⇒ 得到字符下标却当 byte 报出**，中文多字节 ⇒ 必然偏小；"没写计算式"才让错值看起来像证据）✓
**"0 命中"先问"表/范围对不对"（硬，2026-10-14 实测）**：实测 —— 在 `ledger.tsv` 里搜某片的 `OCCUPY|RELEASE` = **0 命中**（那两个动词其实写在 **`play-log.tsv`**）⇒ 若据此判"它没取槽"就是**假阴性**。⇒ 规矩：**"0 命中"先验证"检索的表/目录/范围是不是应有它的那个"**（与"按前缀清点漏 13 件"同族：**清点范围靠猜 = 结论靠猜**）。
**规范要写成"动作"，⛔ 不是"原则"（硬，2026-10-14 两度实证）**：实测 —— 某片**两次**把"按内容确信才删"这类**原则**用成了"按类目/文件名判"（两次都被**"请先跑一次引用检索，命中即 ABORT"**这个**动作**挡下：其中一批是别人的报告与收尾文档在引用、另一批是**项目级体量预算历史的唯一记录**）。⇒ 规矩：**把可执行的动作写进规范**（"删前跑引用检索"、"写后回读断言"、"先用已知阳性验检测器"），⛔ 只写"要谨慎/要确信"这类形容词等于没写。
**⛔ PowerShell 参数名禁用「自动变量名」（硬，2026-10-14 实测事故根因）**：实测 —— 一个辅助函数写成 `function K($f,$args,$pats){ … & python $f $args … }`，调用 `K <脚本> '--dry-run' @(...)` ⇒ **`$args` 是 PowerShell 的自动变量** ⇒ **`--dry-run` 被静默吞掉** ⇒ 实际执行 = `python <脚本>`（**无参数**）⇒ 而该脚本的默认分支是 **APPLY** ⇒ **真的写了盘**（在"未放行窗口"内）。⇒ 规矩：**参数名⛔ 禁用** `$args` / `$input` / `$error` / `$host` / `$matches` 等自动变量（用 `$extraArgs` 之类）；**包一层调用时必须原样打印"实际命令行"（用值、非参数名）+ 断言参数已到达**（让被调脚本自报 mode）✓
**会写盘的脚本：默认必须是 dry-run，写盘要显式 `--apply`（fail-closed）（硬，2026-10-14 采纳）**：理由原话 —— "**谁跑了它不可控，但默认值可控**"；而当时这类脚本的默认值**恰是"最危险的那个动作"**（`DRY = '--dry-run' in sys.argv` ⇒ **不带参数 = 直接写**）。⇒ 凡是"会追加/覆盖共享件"的脚本，**默认 dry-run**、写盘**必须显式 `--apply`** ✓ 并配套：**凡"是否写盘"的问题，⛔ 不许靠 grep 过滤后的输出判**（至少保留脚本自报的 `DRY RUN` / `WROTE` / `ABORT` 三类行 —— 实测有人**被自己的输出过滤器骗了**：它的过滤式恰好吃掉了写入确认行）✓
**"脚本自证不写" ≠ "本次调用没写"（硬，2026-10-14 实测的方法论修正）**：实测 —— 指挥者用"读脚本（`--dry-run` 分支在写盘前退出）+ 查自己的时间线"来排除，**只够排除"脚本有 bug"和"我自己"**，**不足以下"没人写过"的结论**（实际是"被调时的参数被吞"）。⇒ 正确排除法：**核调用参数** 或 **现场后验（mtime/sha）** 或 **让文件里留下"谁在跑"的痕迹** ✓
**"结案"要落到唯一作者（硬，2026-10-14 实践）**：一旦查明，**立刻广播结案**（⛔ 别让其它片继续白自查）；同时**把结论写准**（本次 = "由该片自己执行、原因是参数被吞"），⛔ 不要写成"未知第三方"、更不要写成"由指挥者执行" ⇒ 否则**归因错**会被永久写进报告 ✓

**"一次减法"即可判定 char/byte 口径（硬，2026-10-14 实测，强烈建议采用）**：**同一位置两个口径都算，看差值** —— **差 = 0** ⇒ 该点之前全 ASCII（**两口径同值，标签仍须写清**）；**差 > 0** ⇒ **差值 = 该点前多字节字符的额外字节数** ⇒ **若你引用的数落在"小的那个" ⇒ 那它其实是"字符下标"**。⇒ 实例（**已用"同一遍读取、同一时刻"钉死**）：同一处 CR，`byte = 324943`、`char = 310881` ⇒ **两个数不是"漂移前后的同一偏移"，而是同一位置的两种量法** ✓
⚠️ **公式要写准（本条曾被写错、被实测纠回）**：**`Δ = Σ(len(utf8) − 1) = 14062`（精确成立）** —— ⛔ **不是"非 ASCII 字符数"**：那份前缀里**非 ASCII 字符只有 7053 个**（差 `44` = **44 个"2 字节非 ASCII 字符"每人只多 1 字节**）⇒ ⇒ **若后人按"字符数"去核会得 7053、误判"对不上"** ⇒ 规范里必须写明：**"差值 = 各字符 UTF-8 长度减 1 的总和"，⛔ 不是"非 ASCII 字符计数"**（ASCII 字符贡献 0、2 字节非 ASCII 贡献 1、3 字节贡献 2…）✓

**"共享表"的判据 = 共享 + 被多人追加（硬，2026-10-14 实测）**：做 EOL 归一/行尾纪律时，⛔ **别把"驱动文件 / 产物文件"当"表"**（有人的驱动文件本身是 CRLF、其产物日志按设计是 BOM+CRLF ⇒ **与"表"无关**）⇒ **"表"= 被多方追加的那个文件**；"驱动文件的行尾"属**另一类**问题（若要统一，单独立项、并意识到它会改变该驱动的 sha）。
**审计脚本打印"上下文窗口"会诱发归属错判（硬，2026-10-14 自曝实测）**：实测 —— 一个"找黏行"的审计脚本打印出的那一行，**同时露出"前一行的行尾"与"后一行的行首"** ⇒ 读的人**把 CR 的归属判给了后一行那一方**（其实它是**前一行**的行终止符，两行被黏成一条物理行）⇒ ⇒ 规矩：**审计输出要显式标出"这条记录的边界"（例如打印 `行首指纹` + `行尾指纹`），⛔ 不要让"上下文窗口"看起来像"同一条记录"**。

**"可复检"分三层，各层归属不同（硬，2026-10-14 定案）**：**① 层 = 结论能否只靠「库内文件」重新导出 ⇒ 必须满足**（范例：某片的结论所依据的是"源码静态事实 + 文件读数"，**全在库** ⇒ 报告里明写"本片结论不依赖执行器"）；**② 层 = 原始读数**（在归档、工作区根）⇒ 标"**工作区可读**"；**③ 层 = 重跑实机取证**（依赖 `.ai-tmp` 里的**共享驱动/入口**）⇒ **统一登记为"会话级、不入库"**，⛔ **不逐片提升**（只提一片 = 不成体系；都提 = 要动**共享件**（多片 dot-source 同一路径）⇒ 风险 > 收益）。⇒ **离线判据**（无 Play、无共享依赖）**该提升入库**（如 `tools/probes/`，与同族件同目录）；**Play 执行器**不入库，但**报告必须写"复检最小材料清单"**（哪几件、在哪、依赖谁）。⚠️ **判据脚本若会读 `.ai-tmp` 的件 ⇒ 读不到必须"明确报错 + 说明去哪找"**，⛔ 不许静默跳过（静默跳过 = 让人以为"跑过了没问题"）。
**"CR 计数不变"优于"零 CR"（硬，2026-10-14 实测的取舍）**：给"往共享表追加"写守卫时，有人把断言写成"**CR 计数不变**"而**不是"零 CR"** —— 理由：活表里**有 1 个历史 CR**，若断言"零 CR"⇒ **会卡死全队后续每一次追加**（把"历史遗留"当成"本次违规"）✓ ⇒ **通用口径：守卫要断言"我的写入没有引入/改变某属性"，⛔ 不是"整个文件处于理想状态"**（后者会把别人的历史问题变成你的阻塞）。⚠️ 配套：**能回滚的分支（如"写后回读失败 ⇒ 按写入前长度截断"）若无法用外部手段造出负控 ⇒ 如实标注"该分支未被负控覆盖"，⛔ 不宣称"每条都有负控"**。
**报"某值变了 / 某文件不存在"必须给检索式，且"变了的旧值"也要能被查证（硬，2026-10-14 实测）**：实测 —— 有人报"某偏移已漂到 X"，另一个片**在盘上复算不出 X**（现盘唯一那个字符仍在原位）⇒ 追查发现 X 是**"用字符下标冒充字节偏移"算出来的错值**（**从未在盘上存在过**，是 bug 的产物、不是"曾经的读数"）⇒ ⇒ 规矩：**① 报"变了"必须给检索式（文件 + 关键词/判据 + 时刻）**；**② 引用"旧值"前先确认它曾是"盘上事实"**，⛔ 别把"算错的中间值"当历史；**③ 行/记录的归属以「行首指纹」为准**（口语里"落在某片行内"常有歧义）。：实测 —— 某驱动是**逐字复制**另一片而来，留下**第三种残留**：它的**活代码在读取"原片名下"的文件**（`$secFile = …\botflip-seconds.txt`）⇒ ⇒ **改/删那个文件会打断别人**。⇒ 规矩：**复制驱动后必须做一次"借用扫描"**（别人片名/文件名/actor 名/心跳名/待读文件），并**把值内联或改成自己的名下**。**⚠️ 另：快照的 `mtime` 必须注明"是源文件时刻、还是副本创建时刻"**（`copyfile` 与 `copy2` 语义不同）—— 否则 **EOL 等列会被误读**（实测两份快照 CRLF/LF 不同、无法判断是"归一发生在其间"还是"mtime 语义不同"）。

**"清单 / 表头"本身也必须被断言（硬，2026-10-14 自曝实测）**：实测 —— 某清单的表头本该是 **1 行**（`# file<TAB>bytes<TAB>sha…`），实际**被写成 5 行**（tab 变成行分隔）⇒ 后果 = **"清单数据行 = 18"这种假计数**（14 条真数据 + 4 条只含 tab 的伪行），而且**连刷 4 次都没被发现**（每次都是"刷新成功"）。⇒ 规矩：**凡生成 TSV/清单，写后回读并断言「表头单行 + 数据行数 == 目录件数（1:1）」**；写 tab 一律**显式 `[string][char]9`**，⛔ 别靠字符串里的制表符字面。
**删文件 = "内容确信 + 查引用"（⛔ 别按文件名像不像临时件）（硬，2026-10-14 实测）**：实测 —— 有人把某批产物里 7 个大件按**文件名**判成"删除候选"，**删前查引用当场推翻**（它自己的报告明列为"分析用探针"，**且另一人的收尾文档也引用它们**）⇒ 0 件删除。⇒ 规矩：删之前**按内容确信**、并**检索引用（含别人的报告/收尾文档，不只是自己的）**；"像临时件"⛔ 不是理由。范例：有人给归档脚本加了**每件回读比 sha**（失败 ⇒ **不打印成功** + 返回码 2），并**真跑**阴阳性对照（负控 `rc=2` / 正控 `rc=0`）；另一人自查到"**收工段无条件停编辑器**"会在"取锁后、进 Play 前中止"的路径上**掐掉别人的会话** ⇒ 用 `droveEditor` 门控 **＋ 新增第 4 格负控**（断言**日志里无 `[stopfinal]`**、仍 Release、仍写 `play end`）。

**行内表：字段里插换行 = 让内容对该表的 id 索引「隐形」（硬，2026-10-14 实测修正）**：实测 —— 有人往表里追加"闭环块"时写成 `字段 + "\n\n" + 块` ⇒ 块落到**空行 + 独立物理行** ⇒ **按首列 id 读表的工具看不到它**（那条"已关"的结论对 id 索引**隐形**；也造成"行数口径差"）。⇒ 修法 = **只删多余换行、把块并回同一物理行**（行数 −2、id 行数不变）。⇒ **定案：追加"闭环/结论块"时⛔不许插空行**（要用就用 `\t`、或续写在同一字段内）。
**"两行黏成一行"的扫描器必须用「紧邻行首模式」判，⛔ 别用"一行两个时间戳"（硬，2026-10-14 实测）**：实测假阳性 **7/8** —— 用"行内 ≥2 个时间戳"扫出 **8 行**候选，其中 **7 行的第二个时间戳是行内合法引用**（引别人的日志/心跳值），**真黏行只有 1 行**。⇒ 判据必须含：**第二个时间戳紧邻行首模式 `日期T时间\tactor\t动词`，且前邻字符不是空白** ⇒ ⛔ 否则会把好行改坏。
**整文件替换（表 / 代码件 / 状态件）一律「临时文件 + 原子 Move」；该定案会覆盖到已交付工具（硬，2026-10-14 定案）**：实测 —— 有人交付的 EOL 归一工具对共享表用**裸 `WriteAllText`（整文件、非原子）** ⇒ 已改为同目录临时文件 + `[IO.File]::Move($tmp,$Table,$true)`；另有片登记"对共享**代码件**做过非原子整文件替换（有备份 + hunk 次数==1 否则零写盘 + 反向逐位校验）"、以及"对共享**状态件**做过 2 次非原子覆写"。⇒ **读-改-写只准"行内定点、行数不变"**；其余一律原子替换。
**"行内 RMW"的加严版 = 写后**复读行数**（硬，2026-10-14 实测）**：行内 RMW 只断言"除该行外逐位不变"**不够** —— 若"读→写"窗口内**有人追加了一行**，你的写回会把它抹掉。⇒ 规格：**写前快照 → 写 → 写后复读行数（变多 ⇒ 说明有人并发追加 ⇒ 必须重合并，⛔ 不当成功）→ 报前后 sha**。
**表对账读 `owner` 会得到假警：锁定对象在 `named=`（硬，2026-10-14 实测）**：实测 —— 某表的 `owner` 字段 = "**谁写的这行**"，而"**锁定对象**"在 `named=` 字段（同一人可代持别人的 `named`）⇒ 按 `owner` 做 `OCCUPY/RELEASE` 配对会跑出**大量"未配对"假警**。⇒ 要真核：**以 `named=` 为键 + 剔除 NOTE/bookkeeping 行**。

**共享表写入方式定案：追加 = 单次「追加语义」写入（`AppendAllText` **或** `open(...,'a')`）；⛔ 追加类禁用「读-改-写」（硬，2026-10-14 自曝实测）**：实测自曝 —— 用 `ReadAllBytes` + 拼接 + `WriteAllBytes` 往共享表**追加**，**存在一个窗口会静默丢弃别人的并发追加**。⇒ 定案：**① 追加行 ⇒ 单次 `[IO.File]::AppendAllText`（追加模式）**（并注意**前缀换行**：⛔ 漏了会把两行**黏成一行**，实测已发生一处，按行读表的工具会把它们当一行）；**② 整文件替换 ⇒ 写临时文件 + 原子 Move-replace**；**③ 读-改-写只准用于"行内 RMW 且行数不变"的定点更新**（改一行、总行数不变、写后复读）。
**多信号互证必须「同一次取」，⛔ 不许跨时刻拼接（硬，2026-10-14 实测）**：实测事故 —— 两次读数**相隔约 16 秒**（`04:01:08 PRESENT` vs `04:01:24 ABSENT`）被当成"同一时刻"⇒ 得出**假矛盾**、被误记成"工具两行合并的 bug"（复核证明两行**分开且可读**）。⇒ 规矩：**同一次命令、同一瞬间**取完所有信号再下结论；**跨时刻的读数只能各自成立、⛔ 不能互相"佐证"或"证伪"**。（配套：`-Probe` **第一行** = 文件事实、可信；**第二行** `ledger tail` = 台账历史、⛔ 不是锁状态。）
**"复制 / 写入成功"的断言：件数只是必要条件，必须核内容哈希（硬，2026-10-14 自曝实测）**：实测事故 —— `Copy-Item -LiteralPath <src>\*`（**`-LiteralPath` 不做通配符展开**）⇒ **一件也没复制**，而"**只数件数**"会判 PASS（`54==54`、两边都是 54）；**因为顺手比了一个内容哈希才发现**。⇒ 规矩：**断言效果 = 件数 + 至少一个内容哈希（或整目录摘要）**；并要求同族自查 **PS 变量名大小写不敏感**（`$S`/`$s` 是同一变量 ⇒ 实测有人 `$s=@()` 把源路径覆盖成空数组 ⇒ 打印"src files = 0"，**看着像"目录不存在"**）。
**"不存在 / 0 命中"的检索式必须能被他人复算出同一结论（硬，2026-10-14 主 agent 第三次同类错）**：实测事故 —— 报"某句已不在文件里"时，**搜的关键词与目标句不是同一句**（搜 `without looking at`、目标句是 `…Get-Item agree),`）⇒ 据一个**不相关的 `False`** 下了"已不存在"结论，**复测才发现目标句仍在**。⇒ 规矩：**报"不存在"必须同时给出"文件 + 关键词 + 判据 + 时刻"**，且**换一种写法/换关键词复算一次**（与"猜路径得假 ABSENT""`-Filter`+`-Include` 假 0 件"同族 —— 这是**第三次**）。

**⚠️ 连"不可复核 / 不存在"这类结论本身，也必须先"给检索式 + 找一遍"（硬，2026-10-14 主 agent 第四次同类错）**：实测事故 —— 广播"某份快照在任何副本上都复现不出来 ⇒ 属**不可复核**"，**而那份文件就在盘**（另一片当场给出四元组：`路径 + bytes 453374 + sha256 6349FDC1… + records/uniq 196/195 + max 222 + mtime 01:49:34`，另有两份镜像逐位同 sha）⇒ 错因 = **只凭"我没见过这份文件"就下了否定结论**。⇒ 规矩：**下"不可复核 / 不存在"结论前，必须先给出检索式（或请持有方贴四元组）**；正确表述是"**我按 X 检索、未能找到**"，⛔ 不是"它不存在"。⇒ 同族四次：猜路径（假 ABSENT）→ 搜错关键词（假"已不在"）→ 记档不准（把"在途读"写成"假读数"）→ 凭印象判"不可复核"。

**"某文件是否仍被引用 / 仍生效"⛔ 不能用「文本存活率」判（硬，2026-10-14 自曝实测）**：实测反例 —— 想用"逐行看哪版代码还活在盘上"自动判"是否已被取代"：`gate26i.py/gate26j.py` 得 **0%**（作者用**紧凑拼接**写 PowerShell ⇒ 长行匹配全落空 ⇒ **假 0%**），而 `gate26h.py` 得 **28%** 来自**共同锚点行**（**假高**）⇒ ⇒ 判据本身不可靠 ⇒ **⛔ 更不能用它决定删文件**（可能删掉"仍在盘上生效"的生成脚本）。⇒ 删文件只认**按内容确信的一次性件**（且先"零引用"双实现核过）。
**表对账：用「id 集合 + 最长公共前缀」，⛔ 不用"整行相等"（硬，2026-10-14 实测）**：实测 —— "整行相等"会把 **7 处"内容被就地改写"**的行**误报成 7 个丢行**；正确判法 = **id 集合差集**（`GONE=0` ⇒ 无丢行）+ **最长公共前缀**（区分"纯追加 / 就地改写 / 真丢"）。⇒ 并**必须写明 id 的定义**（实测两片因定义不同得出 `196/223` 与 `195/222` ⇒ **不可比**）：**"id = 首个 TAB 之前的全数字"** ✓
**"双实现"必须配「阳性对照」（硬，2026-10-14 自曝实测）**：实测反例 —— 有人写第二实现时把"**文件路径**"当内容管道进检索工具 ⇒ **目标 6 族全 0 命中**，而**阳性对照也是 0**（该词组在报告里必然存在）⇒ **一眼判"检索器坏了"**；改正后对照得 `A-vs-B 25 / CsDecalAlphaClip 14 / DecalCutoff 17` ⇒ ⇒ **没有阳性对照 ⇒ 会把"坏扫描器的 0 命中"当成"干净"上报**；有对照 ⇒ 当场抓住坏实现 ✓
**"拒绝/中止"分支也要写台账行（硬，2026-10-14 自曝实测）**：实测缺口 —— 守卫判"拒绝"后执行了 `Release` + 退出，**但没写台账行** ⇒ `play-log` 留下"**有 OCCUPY 而无 RELEASE**" ⇒ **看着像"锁还在"**（正是今晚反复咬人的那一类）。⇒ 修法：**拒绝分支内补一行 `RELEASE(refused): <原因>`**（append-only、LF、无 BOM）✓

**"0 命中 / 不存在"必须给可复算检索式 + 换一种写法互证（硬，2026-10-14 实测）**：实测 —— `Get-ChildItem -Filter 'blendfix-*' -Include '*.py'` **返回 0 件**（差点被当成"我没有脚本"），换成"**先 `Get-ChildItem` 列全、再 `Where-Object Name -like`**"才看到 **7 件**；另一路同族事故 = **自拼路径**（`.ai-tmp\play.lock` vs 真 `.ai-tmp/test/play.lock`）⇒ 假 ABSENT。⇒ 规矩：**报"不存在"前用两法互证**（如 `Test-Path -LiteralPath` + `[IO.File]::Exists` + 目录枚举），并**把解析后的绝对路径印出来**。
　**再加两条（同晚实测）**：**① 正则也要"更宽的写法"** —— `version\s*==\s*2` **匹配不到** `chk["version"] == 2`（下标写法）⇒ 会给出**假 0 命中**（放宽 + 换实现后**抓到真命中 1 处**，正是那条会 9/9 假失败的脚本）⇒ **换实现时同时放宽"写法变体"（下标 / 引号 / 换行 / 全角符号）**；**② "0 命中"是带时间戳的快照、会过期** —— 同一问题 `glob` 给 17 件、`cmd dir` 给 23 件，多出的 6 件是**之后才创建的沙盒**（各带自己的 `play.lock`）⇒ 复算必须写成 **`as of HH:MM:SS | 检索式 | 第二实现 ⇒ 均 0`**（⛔ 否则会把"后来新增的"读成"当时报错"）。

**"白名单化"必须同时确认"真正的成功长什么样"（硬，2026-10-14 实测）**：闸门把放行条件收窄成**白名单**（只认 `up_to_date`）是**对的**，但配套缺了一条：那个动作的**成功形态**是**散句/纯串**（真原文见 ≥6 份已有产物：`recompile true up_to_date：No scripts needed recompilation.` / `recompile_status true up_to_date`；**没有 `"status"` 键**）⇒ **正则抓不到** ＋ **白名单只认该值** ⇒ ⇒ **每次成功都落 `noverdict` ⇒ 恒拒**。⇒ 规矩：**① 收窄放行条件时，必须同时拿到"成功/失败各自的真原文"，并各写一格断言**（⛔ 别只写失败格）；**② 同一动作可能有多种成功形态**（本例两行：`recompile` 与 `recompile_status`）⇒ **锚要选"渲染无关"的**（`^\s*recompile\s+true` **且** 含 `up_to_date` **且** 不含 `failed`），⛔ 别只匹配其中一种；**③ 抓不到的形态要显式广播"这是已知缺口"**，否则排队者会把它当成"工具又坏了"、白转一圈。

**清"陈旧锁"的四条件 AND（硬，2026-10-14 两次修正后定案；⚠️ 本条曾因缺第 4 条导致一次误清）**：只有在**四条全真**时才允许"清陈旧锁 + 留痕"；**任一条不可判定 ⇒ fail-closed（不动锁）**：
1. **租期**：`play.lock` mtime 年龄 > N（持锁者应每 ≤N 分钟 `-Touch` **或在台账写一行**）；
2. **心跳**：`<owner>-heartbeat.txt` **不新鲜**（若心跳新 ⇒ **判"仍在跑" ⇒ 拒绝清锁**）；
3. **编辑活动**：`editor_status` 可判定且非 `playing`，**且** `play-driver-log.tsv` 静默 > N；
4. **⚠️ 全仓活动（**最容易漏、也最致命**）**：**"最近 N 分钟内被修改的文件"**（`client/Assets/**`、`Library/ScriptAssemblies/**`、`Logs/**` 等）—— **有新写入 ⇒ 判"仍在跑" ⇒ 拒绝清锁**。
⇒ **最后一道（最实用）**：**直接问持有者**（团队内可寻址就发消息问"你还在跑吗"）；⛔ 别"先清后问"。
⚠️ **两个洞见（都来自实测事故）**：
- **"非 Play 的长活"在锁与驱动日志上完全不可见** —— `play-driver-log.tsv` **只在 Play 时写** ⇒ "驱动日志静默 41 min" **与"它在跑生成器/大批重写资产"完全相容**（生成器不写 driver log、也不 `-Touch`）⇒ **所以"锁 mtime + 驱动日志"两条同时静默 ≠ 已死**。
- **`client/Logs/Editor.log` 的 mtime 只证明"编辑器没死"，⛔ 不能证明"锁持有者没死"**（它几乎永不静默 ⇒ 是**噪声信号**）⇒ 判活跃/死亡以 **`play.lock` mtime + `play-driver-log` + 全仓活动** 为主。
⚠️ **"无心跳 ≠ 已死"**：驱动**本来就没做 `-Touch`** 时，mtime 不刷新是**预期行为**，不是死亡证据。

**"安静是常态"——判活动/停止必须按"突发节奏 + 长窗 + 直方图"（硬，2026-10-14 实测）**：实测某批资产写入有**两段截然不同的速率**（`03:55–03:59` 每分钟仅 4–12 件 vs `04:00–04:03` 的 102/150/172/78）⇒ **"静默 3 分钟"完全落在它自身的间歇内** ⇒ ⇒ ⛔ **单点 `newest`/单分钟读数会把"批间间歇"误判成"停止"**（也会把"停止"误判成"在跑"）。⇒ 规矩：**用 ≥10–15 分钟窗 + 每分钟直方图**，并**与该事务自己的历史间歇长度对比**；定性的**唯一硬证据是"问发起方"**。
**"调用终止" ≠ "产物停止写入"（硬，2026-10-14 实测）**：某异步成员的调用已终止，但它的产物**仍在被写 ~3 分钟**（"生成器已退、Unity **导入尾流**仍在写 meta"；特征是文件名 **`.asset` + `.asset.meta` 成对**出现）⇒ ⇒ 判"它是否还在活动"要看**写入面**，而不是"调用状态"。
**"两侧对比"类判据：两侧素材都要留"与工作树解耦的副本"（硬，2026-10-14 最佳实践）**：实测某比对脚本**附带走还原**（`git checkout --`）⇒ 谁跑它就会**抹掉别人目检要用的"重生成版"素材** ⇒ 最佳实践 = **把两侧素材各冻结复制进归档**（含 `README` 记取数时刻与方法 + sha）⇒ 判据**不再依赖工作树**。⚠️ 同时**给这类"会带还原动作"的脚本发操作禁令**（比较只用**只读哈希**）。
**"引用式命中"要显式标注（硬，2026-10-14 实测）**：改了某条判据后，新文本里**引用**了旧判据原文 ⇒ `grep <旧串>` **仍会命中该行** ⇒ 后人会读成"漏改" ⇒ **在行内注明"此处为出处引用"**（与"假 0 命中"对称的**假阳性**）。

**"异步成员"没有"已结束"这个默认推论（硬，2026-10-14 主 agent 亲历）**：派给**异步 team member**（带 `name=`）的调用，返回的只是 **spawn acknowledgement**；⛔ **不能据此推断"任务已完成 / 它已终止 / 它的锁已成滞留锁"**。实测事故：主 agent 据此判"持有者是已终止的 subagent ⇒ 不可能自己 `-Release`" ⇒ **误清了一把活人的锁**（损失=0 纯属侥幸：当时无人 acquire、且对方在做非 Play 工作）。
⇒ **清锁由指定单方执行**（⛔ 不许"谁在场谁删"）：`-Probe` 记录 → **物理删除** → **三法互证 `Test-Path=False`** → `play-log.tsv` 追加 **`CLEARSTALE`** 行（含 `owner`/`since`/`age`/**证据摘要**/裁定人）→ **广播**。
⇒ **根因改进**：**派 subagent / 派片时，指令里必须写明"结束前必须 `-Release`"**（不写 ⇒ 滞留锁 ⇒ 全队排队）。

**版本/格式断言要"容忍集合"，不要写死单个值（硬，2026-10-14 实测）**：`.cs16anim` 现盘已是 **v3**（`#10` 线 02:19 升版 + 02:29 重导出 1.47 MB → 4.79 MB）⇒ 任何"判 `version==2`"的旧断言**9/9 假失败**（**假失败与真缺陷同形，最费时间**）⇒ 写成 **`∈{2,3}`**（该段布局自 v2 起未变）。⇒ 通用口径：**读"版本 / 枚举 / 可选字段"时一律接受已知集合 + 未知值报错（而非静默当某个旧值）**。

**PS 5.1 落盘编码陷阱的完整清单（硬）**：`>`（重定向）**与** `Tee-Object -FilePath` **与** `Out-File` / `Set-Content -Encoding utf8` **都会产非预期编码**（实测：`Tee-Object` 产 **UTF-16LE+BOM**，7 件一次；`>` 产 UTF-16LE）⇒ **证据落盘一律** `[IO.File]::WriteAllText($p, $s, New-Object System.Text.UTF8Encoding($false))` **或** python `open(p,'w',encoding='utf-8',newline='')`。⇒ 已产出的**不重编码**（采集即冻结）⇒ 补 `ENCODING-NOTE.txt` + MANIFEST 加 `encoding` 列（注明**正确读法**：UTF-16 ⇒ PS `-Encoding Unicode` / python `encoding="utf-16"`；**`grep` 报 binary = 编码、不是损坏**）。

**追加一行到共享表后必须自检**（2026-10-13/14 多次事故的共性 = 写盘后没验）：① 行数增量 **== 1**；② 追加行**列数正确**（`ledger.tsv` = **3 列**）；③ `CRLF` / `loneCR` **不得增加**；④ **脚本改表时**：改动前后「**不符合列数的坏行集合**」必须**逐项相同**（= 不变量断言，`wheelfix` 实践 ⇒ 防"顺手改历史行"）。
⛔ 改动**历史行**须**显式授权**；「影响待评」类历史瑕疵（如 `ledger.tsv` 142..154 的字面 `` `t ``）**默认不改**。

**两条最隐蔽的坑（都实际发生过，各把整表行尾翻过一遍）**：

| 写法 | 坑 | 正确写法 |
| --- | --- | --- |
| Python `open(p,'w')` / `open(p,'r')`（默认 `newline=None`） | 读时把 `\r\n` 收成 `\n`、写时再把 `\n` 摊成 `\r\n` ⇒ **整表行尾被翻**，且 `lone_CR=0`（看不出破绽） | `open(p,'wb')` 写字节，或显式 `newline=''` / `newline='\n'` |
| PowerShell `[IO.File]::WriteAllLines($p,$lines,$enc)` / `Set-Content` / `Out-File` | 用 `[Environment]::NewLine` 连接 ⇒ Windows 上全变 `\r\n` | `[IO.File]::WriteAllText($p, (($lines -join "`n") + "`n"), (New-Object Text.UTF8Encoding($false)))` |

**第三个来源（无法靠写法避免）**：**宿主（编辑器 / IDE）自带的写文件工具**在 Windows 上按平台写行尾 ⇒ 它生成的文件天然是 CRLF。⇒ 对这类文件：**要么连同归档 `MANIFEST.tsv` 的 sha 一起重算后再转**，要么**明确它们不进"共享表"口径**（「**采集即冻结**」的证据件 → **一律不动**，改了会让归档 sha 全对不上）。

**改写共享文件前的固定动作**：
1. 读最新 → 只改命中行 / 追加行 → **保留探测到的行尾**；
2. 写回后做**字节级校验**：把你改的那一行（或那几行）剔除后，其余内容应**逐位等于改前**；同时报 `CRLF / loneLF / loneCR` 计数与行数；
3. **异常立刻在回报里写明**，别吞。

**行尾分层口径**：`client/**/*.cs` 保持原生 CRLF；`策划/**` 与共享表用 LF；`.ai-tmp/**` 的临时产物**不强制**（别为它花片子的时间）。

## 进 Play 的抢槽协议（硬）

**唯一权威 = `take-slot.ps1`（全队共用）**。⛔ 各片自己的驱动**不许自己建锁 / 删锁 / 写 `OCCUPY`·`RELEASE` 行** —— 这三样正是"两人同时在 Play"的入口（2026-10-13/14 各片实证）。

| 环节 | 硬要求 | 为什么（都是实证） |
| --- | --- | --- |
| 建锁 | **原子创建**（`[IO.File]::Open(…, CreateNew)` / `os.open(…, O_CREAT\|O_EXCL)`）；已存在即失败退出 | 覆盖写建锁 = 两人同时进 Play |
| actor | 一律 **`<片名>-<用途>`**（**纪律**）。⚠️ **现态：`take-slot.ps1` 只校验"非空"（`:469`/`:486`），格式**未被机器强制**（`<片名>-<用途>` 那句在 ~`:80` 只是注释）**；格式强制 `^[a-z0-9]+(-[a-z0-9]+)+$` 已派修，落地后本节改为"机器强制" | 裸片名他方识别不出；**两个片传同一裸名时共享件会判为同一方**（`sameParty` + 已释放豁免 ⇒ A 干净释放后 B 的 OCCUPY 反被判成 sameParty）⇒ 正是"第二次 take 覆盖活锁"的形态 |
| owner 判定 | 解析 `owner=<name>` 后**整串精确相等**（`-ceq` / `-eq`） | ⛔ 子串 / 前缀匹配（`-match` / `-like`）会把 `<我>-other` 判成自己 ⇒ 撞车入口（用反向对照实证；全仓已清 2 处） |
| 进 Play 前的 gate 2 | 必须**真读到 `playMode`**：只有 `stopped` 才继续；`playing` ⇒ 拒；⛔ **`noled` / `unknown` 一律归"无判定" ⇒ 复读一次（`Start-Sleep 8`）⇒ 仍无则拒绝** | 旧口径"`noled` == 空闲"会把**正在 Play 的会话**判成"可以上槽"（实证：编辑器在 Play、gate 回 `noled`） |
| 调 unity-cli | **先设进程 cwd**：`[Environment]::CurrentDirectory = <项目根>\client`（⚠️ `Set-Location` **不改进程 cwd**）+ 每条 CLI 带 `--project-path <项目根>\client` | 编辑器发现是 **cwd 相对的**：同一条命令在项目根 = `noled`，在 `client` = `ready` |
| 收工 | **先 `take-slot.ps1 -Release`（认到 `RELEASE OK`）**，再 `editor_stop` + 回 Boot | 先放锁后停编辑器是安全的（gate 2 会拦住下一片） |
| 记账闭环 | 每次占用**必须配 `RELEASE`**，或配一条**显式 `NOTE`**（说明"连续占用、未释放"） | 账上不得出现"两次占用零次释放" |
| `[IO.File]::*` 路径 | **一律绝对路径** + `Test-Path -LiteralPath` 显式验；⛔ 不吞错误 | 相对路径按**进程 cwd**（不是脚本所在目录）解析 ⇒ 会在项目树外**静默新建**文件 |
| 权限 | 无 Play 需求**不要建锁**；槽被别人持有时**不许抢**（等、或`-Release` 自己的） | — |

**⛔ 同级纪律（2026-10-14 实测）**：**写会触发重编译的源码**（`client/Assets/Scripts/**` / `client/Assets/Editor/**` 及一切 `.cs`）**之前必须持槽**，或先确认 `playMode=stopped` 且 `play.lock` 不存在 —— Editor 脚本写入会**触发重编译、可能重启他方正在跑的 Play**，**破坏力与"抢 Play"同级**（毁掉别人的取证）。实测：某片 Play 窗口内（03:10:40–03:16:27）他片写了 `Assets/Editor/MapGen/*.cs`（03:11:32–03:12:17），本次因噪声地板 = 0 未干扰，但属队列纪律风险点。

**"字面符号"⛔ 别喂给 `-like`（硬，2026-10-14 自曝实测的假计数）**：某人用 `Where-Object { $_ -like '??*' }` 想数 `git status` 的未跟踪行 ⇒ **`?` 是单字符通配符**、`'??*'` 匹配**任意 ≥2 字符** ⇒ 命中**全部 3,024** 行（真值 **2,802**）；换**正则**（`-match '^\?\?'`）后正确（`2,802 + 222 = 3,024` 严丝合缝）⇒ ⇒ **凡"按行首标记 / 字面符号"计数或筛选，一律用正则或 `StartsWith`**，⛔ 不用 `-like`（`?` / `*` / `[` 都是通配符）。⇒ 与另两条同族：**超串锚点**（吃错了对象）、**通配符当字面**（把字面当模式）—— **报数前先问"我的判据把什么当成了什么"**。

**T3 内部再分三个标记：`T3!`（整文件重写 / 整表 RMW）· `T3`（追加一行）· `T3r`（行内定点 RMW）（硬，2026-10-14 采纳）**：同为"无参即改共享真表"，**危害不同档** ⇒ **`T3!` 最险**（`open(P,'wb')` / 整表读-改-写 ⇒ **会覆盖或回退他行、可能压掉并发追加**）｜**`T3` 追加**（只增行；风险 = 重复行 / 污染，**不会丢别人的行**）｜**`T3r` 行内定点 RMW**（只改指定行；带"**目标行恰 1 次命中，否则 ABORT 且不写盘**"守卫者风险最低）⇒ **名册里三者分行写**，⛔ 别混成"改真表"一条（会既冤枉追加器、又淡化整表重写）。

**`git check-ignore` 对"仓库外绝对路径"的 rc 是伪影（硬，2026-10-14 实测）**：实测 —— 传**仓库之外的绝对路径**给 `git check-ignore -v` ⇒ rc ≠ 0（看起来像"未被忽略"）⇒ **⛔ 不能据此判"可提交"**。⇒ 判"可提交"的正确形态：**在仓库内、用仓库内的相对路径（或仓库内 cwd）**跑 `git check-ignore` / `git status --porcelain`；⚠️ 工程外的权威根 / 归档件**一律不入库**，与 ignore 与否无关（`.ai-tmp/**`、`_cs16-evidence/**` 的规则已在库里写着）。

**补丁类交付必须跑一次 `git apply --check`，`rc=0` 才算交付（硬，2026-10-14 实测两次同族事故）**：① 某补丁的"正/反向内存回放 True"**证明不了**它能被 `git apply` 读 —— 实测 `git apply --check -R` **rc=128**（`error: patch fragment without header`），根因 = 生成器 `"\n".join(header+diff)` 而 `difflib.unified_diff` 的结构行（`---`/`+++`/`@@`）**自带 `\n`** ⇒ **每处后多一个空行**（正文行因目标 CRLF 反而"恰好正确"）② 另一例：生成时用 `str.splitlines()` **把 CR 吃掉** ⇒ `git apply` **静默 `Skipped patch`**（不报错！）⇒ ⇒ 规矩：**补丁交付判据 = ① `git apply --check`（已应用态 `-R`）`rc=0` ② `--numstat` 给真行数与预期一致 ③ 明确"读法/行尾"**；⛔ 自研回放器**不能**替代；⛔ `Skipped patch` 这种"静默跳过"还要**看输出**不能只看退出码。
**`.patch` 类文件豁免"文本件统一 LF"（硬，2026-10-14 实测）**：对 **CRLF 源文件**的 `git diff` ⇒ **补丁体必须带 CR** 才能匹配目标行 ⇒ ⛔ **绝不能把 `.patch` 卷进"统一行尾"批处理**（否则整条补丁废掉）。⇒ 口径：**"文本件今后 LF"显式豁免 `*.patch` / `*.diff`（体随目标行尾）**；⚠️ 配套 = 生成补丁的代码**别用 `splitlines()` / 别 `rstrip("\n")` 正文行**（那会吃掉 CR），只用 `rstrip("\n")` 修**结构行**的多余空行。
**脚本里别用单字母函数名 / 变量名（硬，2026-10-14 实测）**：实测某脚本用 `function H()` 算 sha ⇒ **`h` 是 PowerShell 内置别名 `Get-History`** ⇒ 函数**从未被调用**、两行读数**静默消失**、尾部还抛 `Get-History` 参数错（改名 `ShaHex` 后正常）⇒ ⇒ 规矩：**函数名 / 变量名 ≥ 3 字符且语义唯一**（`ShaHex`/`$BASE`/`$pat`），⛔ 不用 `H`/`$p`/`$P`/`$l`/`$L`/`$t`/`$T`/`$A`/`$a` 这类 —— 本族（**名字解析**类坑）已累计 **6 例**（`$l/$L`、`$t/$T`、`$A/$a`、嵌套数组被压平、`$P/$p`、`H` 别名截胡）。⚠️ 症状特征：**"该打印的行没出现"或"后半段报一个看不懂的参数错"** ⇒ 先怀疑名字被截胡/覆盖。
