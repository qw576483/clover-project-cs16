## 八、UV 方向（角色腿贴图）—— 已定案：**修复正确且持久**

**现象**：角色腿贴图方向不对（上下镜像）。

**三方逐顶点对表**（脚本 `.ai-tmp/test/uvv-mdl.py` / `uvv-check.py`，判据 = 逐条 float32 位相等）：

```
原版 mdl 的 v = t/h   →   .cs16anim 逐条"原样搬"（v 625/625 相等，u 625/625 相等）
.cs16anim 的 v        →   改前资产 = anim.v（未翻转）  ← 即"上下镜像"的来源
                      →   改后资产 = 1 - anim.v        ← 与 Unity 的导入口径相符
代码侧（git show HEAD: 证实改前值）：
  -  uvs[i] = new Vector2(sub.Uvs[i*2], sub.Uvs[i*2+1]);        ← HEAD 未翻转
  +  uvs[i] = new Vector2(sub.Uvs[i*2], 1f - sub.Uvs[i*2+1]);   ← 现在（附注释：GoldSrc 口径贴图首行 = t=0 = 图像下边，导入时纵向翻过 ⇒ 必须取反）
```

**关键点**：这一处**改的是生成器（根因）+ 重建 21 个既有产物**，不是只手工改产物 ⇒ **重跑生成器不会回退**。（我一度担心"手改产物不持久"，核 `git show HEAD:` 后确认不成立。）

**复跑命令**：`python .ai-tmp/test/uvv-mdl.py <原版 mdl 路径> player_T`
⇒ `mdl→anim u 625/625 v 625/625`、`now: v==1-anim 625/625(max 0)`、`bak: v==anim 625/625(max 0)`。

**全量复核结果（9 个角色 / 21 个 Skin，逐条满分、零例外）**：

| 角色 | Skin 数 | `mdl→anim`（原样搬原版） | `now: v==1-anim` | `bak: v==anim` |
|---|---|---|---|---|
| player_T / player_CT | 2 / 2 | 625、42 / 656、56 | ✅ 全满分 | ✅ |
| leet / arctic / guerilla | 3 / 2 / 2 | 763、14、42 / 609 / 598 | ✅ 全满分 | ✅ |
