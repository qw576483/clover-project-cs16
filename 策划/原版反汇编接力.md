## 三、三个结构陷阱（不写下来必踩）

1. **这份 dll 带完整的 ReGameDLL 钩子链层**。⇒ **若某个函数里找不到对 X 的直接调用，先怀疑钩子链**，不要判"它不调用 X"。实例：`m3` / `xm1014` 的 `PrimaryAttack` 里**没有** `FireBullets3` 直接调用，它们走 `call 0x10026710`（`push 9` 弹丸数）—— 那是钩子链派发器（`ret 0x24`），弹种藏在**运行期填**的被挂钩实现体里。要取它们的值需**打钩子链注册表**（`0x1012F5C4` 系列）。
2. **同一份 dll 里有两套武器类**：ReGameDLL 重写版 `CAK47…CXM1014`（**vtable 94~95 项**，调用点都在这里）与 CS 原版 `CCSAK47…CCSXM1014`（**41 项**）。⇒ **做归属只能用前者**。
3. **`.rdata 0x1013D6C4` 起那 30 个等距（`0x17C`）"签名块"不是 vtable**（块内混 ASCII 断言串、无构造函数写它）。按它归属会得到"AK47 的 Spawn 出现在别的块"这类矛盾 —— ⛔ 后续勿再用该结构。

## 四、两条可复用的扫描口径

1. **绝对位移的收录范围**：只收"基址寄存器为 0 的绝对位移"会**漏掉 `mov eax,[eax+0x101A1590]` 这类"寄存器基址 + 指向 `.data` 的绝对 disp"读**（曾因此把奖金表误判成死数据）。正确口径 = **收任何 `0x10000000 ≤ mem.disp < 0x10200000` 的位移**。
2. **静态 `cvar_t` 结构体本身就是运行时对象**（注册处只 `push <结构体 VA>; call [...]`，不回存指针）⇒ 要找某个 cvar 的使用者，**搜「条目 VA + 0xC」**即可（用它定位到 `CBasePlayer::AddAccount @ 0x100683D0`、`m_iAccount = player + 0x1CC`、按 `mp_maxmoney->value` 截顶）。

**归属方法（若还要做新的归属，照这两条链交叉）**：
- 链 A：模型串 / 音效串（`models/v_<id>.mdl`、`weapons/<id>-1.wav`）划出的代码区间（互不重叠）。
- 链 B：**MSVC RTTI 反解** vtable（`_TypeDescriptor` ← `_CompleteObjectLocator` ← `vtable-4`），再找"每个武器类 vtable 内**恰好一个**指向含目标调用的函数的槽"。
- 交叉后用**公开值**（如 CS 1.6 的 `rangeModifier`）做第三重校验。

## 七、与工程现值的核对结论（已采纳）

1. **回合常量的"两套口径"都合规、不该改** —— 1:1 复刻对象是**玩家实际生效的那套**（随包 `server.cfg` 覆盖后的值），出厂默认只是同一 cvar 的未覆盖态。
2. **C4 蜂鸣是唯一确认的机制性错误**（现已改回原版机制）。
3. **`#119` 是"工程本来就对"的清单**（奖金 / 连败 / 部位倍率 / 拆包时长）—— 反向证据同样登记，避免后人重查。
4. **距离衰减的老实现会把远距伤害抹平**（100 m 时 USP/Deagle/M4A1 全为 0）—— 已改为 `pow(rangeModifier, dist_unit / 弹种分母)`。
