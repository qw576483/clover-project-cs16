# 工程坑清单（实测踩出来的，会重复踩）

> 每条都是**本工程里真实发生过**的坑，格式统一：**现象 → 判据 → 正确做法**。
> 新片开工前扫一眼这一页，比看十份报告省时间。

## 一、改 UI 面板：只改 `.cs` 是**看不见的**

- **现象**：给面板加了控件、代码也编译过，但进游戏**看不到任何变化**。
- **判据**：`CsPanelBase.Awake` 里对"已有子节点"直接 `return` —— **面板预制体是生成时就带子节点的**，运行时**不会再调 `BuildLayout`**。
- **正确做法**：改完 `.cs` 必须**把该面板的预制体重出**（走 `FlowSetup.CreatePanelPrefab<T>` 同路径：`LoadPrefabContents` → 清子节点 → `BuildLayout` → `SaveAsPrefabAsset`）。只重出**这一个**，⛔ 不要跑整个 `FlowSetup.Generate`。
- 出处：`flow-small` 改暂停菜单时踩到（2026-09-26）。

## 二、`Art/Mesh/*.asset` 是二进制 ⇒ `git diff` 审查不了

- **现象**：`git diff` 只显示 `Binary files ... differ`，**看不出改了什么**；`--numstat` 还会因二进制返回 `-` 把脚本打挂。
- **正确做法**：这类发布物**不能靠 diff 审**，只能靠三者合证 —— ① **生成器**（改的是生成器还是产物？）② **数据链条**（上游输入 → 中间格式 → 产物，逐条对表）③ **运行时探针**。判据要写成"逐顶点 float32 相等"这类可复算形式。
- 出处：`uv-origin` 改了 21 个网格却无文字裁决；`uv-verdict` 用三方对表定案。

## 三、`Get-Content` 不带 `-Encoding UTF8` 会给出**假告警**

- **现象**：一份完好的 `.tsv` 被读成 `total_lines=96 / rows_5_cols=19`，并列出几十行"列数不对"。
- **判据**：PS 5.1 按 ANSI/GBK 解码了 UTF-8 文件。识别特征：`first_id` 显示成 `# 缂栧彿` 这种乱码。
- **正确做法**：**凡行数/列数类校验，必须显式 `-Encoding UTF8`（或走 Python）**。这与".ps1 无 BOM 被按 GBK 解码"同源，但这是**读取**方向。

## 四、`.ai-tmp` 的体积预算 vs 证据归档（规则冲突）

- **现象**：`delivery-hygiene` 要求 `.ai-tmp` ≤ 200 MB，而 `shot-citations` 要求"被引用的证据必须在 `.ai-tmp` 内可解析" ⇒ 一旦把旧证据移出归档，引用就判悬空。
- **正确做法**：`tools/verify.ps1` 的候选路径已加入**归档根**（`_cs16-evidence/`，工程同级目录），并把"从归档解析到"的条数**单独计数打印**（`by archive`）⇒ **不放松标准**（文件仍须真实存在），也不静默通过。移归档时用 `Move-Item`（可回取），⛔ 不用 `Remove-Item`。
- **实测数字（2026-09-26）**：口径是 **≤300 文件 / ≤200 MB**（`rules-full.md:254`）。当时 `.ai-tmp` = **1075 文件 / 184.3 MB** ⇒ **体积没超，超的是文件数（3.5 倍）**，主体是 `test/` 下 **402 个散落的一次性脚本/输出**（122 `.py` + 135 `.txt`）。而同时 `shot-citations` 显示 **114 张被引用截图里 111 张只能从归档解析到** ⇒ **"文件数"与"引用可达"是两条互相拉扯的线**：
  - ⛔ **不能靠 mtime 批量删**（老的不等于没被引用）。**正确顺序是先建"文档引用白名单"**（把 `策划/**`、`docs/**`、`差异登记.tsv` 里出现的每个 `.ai-tmp/...` 路径抓成清单），**白名单外**的一次性脚本/输出才可清；
  - 零敲碎打地删缓存/空文件收益极小（实测 1075→1066），**要达标必须走白名单法**，且**必须在所有片收工后做**（否则会删掉别人正在用的驱动）。

## 五、写共享文件时的**并发**（多片同时改同一批 `.cs`）

- **现象**：两片同时改 `CsDamage.cs` / `CsMatch.cs`，一方定点替换时另一方已顶移位；出现"我改的行不见了"或编译中途红。
- **正确做法**：① 派片前先算**文件重叠**（哪怕是同一文件的不同函数，也按**函数级边界**划开）；② 改共享文件前**重读**、只做**定点替换**、改完 **grep 自己的锚点**；③ 追加 `差异登记.tsv` 一律用**行前缀定位**，⛔ 不整文件覆盖；④ 看到别人造成的**中途编译红**：等它写完，⛔ 不要去改别人的行。

## 六、追加登记行的**编号冲突**

- **现象**：两片各自按"当前最大号 + 1"追加，结果撞号或插到中间。
- **正确做法**：追加前**先读表尾**确认最大号；发现被占 ⇒ 改号并**在回报里说明**（`c4-beep` 就是这么处理 124-130 被占、自己改到 131-134 的）。

## 七、`差异登记.tsv` 的**行号引用**会随追加漂移

- **现象**：文档里写"见第 103 行"，几轮追加后指向别的内容。
- **正确做法**：引用一律用**编号**（`#103`）而不是行号；代码注释里的 `文件:行` 只作参考，判据以**符号名**为准。

## 八、"离线编译绿"≠"编辑器已编译"

- **现象**：离线宿主编译 0 错，进 Play 却报 `CS1061/CS0117 符号不存在` —— 编辑器里的程序集**还是旧的**。
- **判据**：探针编译时某几个**本应存在的符号报"不存在"**，就是编辑器没编译过这批代码。
- **正确做法**：接完代码后跑一次 `unity command recompile`，再谈"生效"。⛔ 别把离线宿主的编译结果当成"游戏里已经生效"。
- 出处：`feel-verify` 实机验收手感批次时撞到（否则玩家会"感觉什么都没变"）。

## 九、原版数值的"载体"会塌

- **现象**：文档引用的 `server.cfg` / `settings.scr` / `原版数值表.md` **盘上不存在**；引的 `mp.dll` 偏移来自**另一份副本**（同批偏移已被证伪过一次）。
- **正确做法**：见 `策划/原版反汇编接力.md` —— 载体说明、两条扫描口径、三个结构陷阱、已确证与未取到清单都在那一页。

## 十、把"未取到"当成"已知为零"

- **现象**：给未取到出处的武器填 `0`，含义变成"不可穿墙 / 不衰减" ⇒ **行为回退**（Scout 原本能穿 1 层，变成不能穿；19 把枪的远距伤害变高）。
- **正确做法**：**未知 ⇒ 沿用旧行为**（回落），并在注释与登记里写清"待取到后切换"。⛔ 不要把 `0` 当作"没有"的默认值语义。
- 出处：`pen-wire` 初版留 0，被 `#130` 口径纠正。

## 11. 跨文件改名必须同一批落盘（否则挡住别人的 Play）

- **现象**：Unity 报 `error CS0103 'X' does not exist`、Play 门禁拦住（`All compiler errors have to be fixed before you can enter playmode!`），而**离线真编译 `compile-check.ps1` 同时是 PASS**。
- **判据**：`Editor.log` 里那条 `error CS` 只出现一次、属于**一条** `Tundra build failed`，之后日志还有几千行且 `error CS` 归零 ⇒ 是**中间态残留**。分辨"旧程序集"与"真错误"两个抓手：① `Cs16.csproj` 的 `STALE-REF`（dll 时间 < 源码时间）；② `Editor.log` 里同名 error 是否只出现一波。
- **正确做法**：① 改名 / 改签名时**定义与全部调用点放在同一批落盘** —— Unity 会在两次落盘之间抓一次重编，中间态必然失败并挡住当时所有要进 Play 的人；② 看见红字先查 `Editor.log` 时间分布与 `STALE-REF`，确认是残留就等**下一次编译自愈**，⛔ 不要 `recompile` 去打扰正在 Play 的会话；③ 编辑器 dll 比源码旧时，任何"符号不存在"先当**旧程序集假象**处理。

## 12. PowerShell 5.1 两个“解析期”坑（不是运行期，会让整份脚本一行都不执行）

- **`$x = Foo()`**：无参函数在赋值右侧写成**空括号** = **解析错**（`“（”后面应为表达式`，行号指向那一行）⇒ 必须写 `$x = Foo`。
- **`.ps1` 含中文就必须带 BOM**：无 BOM 时 PowerShell 的解析器按 **ANSI** 解码 ⇒ **直接 `parseErrors=1`**（不只是“可能乱码”）。
- **正确做法（发车前三件）**：① `Tokenize` / `ParseFile` 后 `errs.Count -eq 0`；② 有非 ASCII 字节 ⇒ 存 **UTF-8 with BOM**；③ **删掉本轮日志再跑** —— 否则会把上一轮的绿当成这一轮（`Test-Path` 还要确认日志首行时间戳是本轮）。
- **实测场景**：低帧率 Play 取证里，“固定 sleep 等时长”是同一族坑（脚本以为等够了、其实一帧都没走）⇒ 改成**等真信号**（等驱动日志的完成行 / 等采样值到阈值），并让等不到时显式 WARN，不静默出废图。

## 13. 判据的“输入”要和“结果”一起留

- **现象**：清中间态时只留了判据的结果（`vis-*.txt` / `vis-*.png`），把被判据消费的**原始帧**删了 ⇒ 这条判据**从此不可复跑**（再跑 `vis.py <tag>` 直接失败），只能引用固化的数字，别人无法复核。
- **正确做法**：① 清中间态前先问一句“这条判据还能重跑吗”；② **被文档 / 差异登记引用过的判据，至少保证能重跑一次**；③ 确需删输入 ⇒ 在判据输出文件里写明“原始帧已删 / 已归档，重跑需先重采”。
- **正例（对照）**：反汇编类取证的输入是**原版 dll / 源码本身**（只读、原地不删）⇒ `verify.py` / `cluster.py` 任何时候都能重放全部 `VA → file offset → 字节`，天然可复跑。
- **判据本身也要留“怎么算的”**：同一份数据用中心点算与用包围盒算能差 1 帧（`expect-vis.py` 与 `vis.py` 的差异来源）—— 两个口径都留，别只留一个数。

## 14. 系统级命令：“报错”不等于“没生效” —— 动手后必须复核状态

- **实例（实测）**：`Disable-PnpDevice -InstanceId “ROOT\DISPLAY\0000” -Confirm:$false` 抛出异常（日志里只有一句 `FAIL: 常规故障`），但它**已经把那个设备禁用了**；脚本继续往下跑、只留下那句 FAIL ⇒ 不复核状态就会以为“没动成”。
- **后果**：被禁的恰好是本机**唯一活着的显示适配器**（其余 4 张物理卡全是 Code 45 幻影）⇒ 桌面立刻无法调整分辨率 / 显示设置。
- **正确做法**：① 任何会改状态的 PnP / 服务 / 设备命令之后，**立刻**重读状态（`Get-PnpDevice -Class Display | Format-Table Status,Problem,FriendlyName`）并与动手前的快照**逐条比对**；② 动手前先存快照、**回滚脚本与动作脚本同批写好**；③ ⛔ **禁用“当前唯一活着的显示适配器”之前必须停手** —— 那会让用户失去显示，甚至看不到回滚界面。
- **回滚实测**：`Enable-PnpDevice -InstanceId “ROOT\DISPLAY\0000” -Confirm:$false` ⇒ 状态回到 `OK / CM_PROB_NONE`。
