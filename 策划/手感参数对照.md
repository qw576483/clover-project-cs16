> - 原版载体 = `原版资源/cs16src/cstrike/dlls/mp.dll`（1,640,960 B，ImageBase `0x10000000`）。

### 1.1 `GetMaxSpeed` 归属确证依据

> ⚠️ **本小节的方法已被 §5.4 取代**（槽 89 = `Precache` 的字符串会被相邻函数污染，实测误判过 4 把枪）。
> 保留在此只为说明"槽位 78 = `GetMaxSpeed`"这个结构事实。

- 武器类的 vftable 在 `.rdata`，步长 `0x17C`（95 槽）；`GetMaxSpeed` 固定落在**槽位 78**，
  `Precache` 落在**槽位 89**（= `GetMaxSpeed` 槽地址 + `0x2C`）。
- 因此：取值函数指针所在地址 `G` ⇒ 该类 `Precache` 指针在 `G+0x2C`；把那个函数里的
  `models/w_*.mdl` / `models/v_*.mdl` / `weapons/*.wav` 串读出来即得武器归属。
  实测样例（`G` → `Precache` 首串）：`0x1013D9DC` → `models/w_usp.mdl`（USP=250）；
  `0x1013E444` → `models/w_scout.mdl`（Scout=245）；`0x1013DFCC` → `models/w_sg552.mdl`（SG552=210）；
  `0x1013E148` → `models/w_sg550.mdl`（SG550=260/220）；`0x1013F1A4` → `models/w_glock18.mdl`（Glock18=240）；
  `0x1013F320` → `models/w_galil.mdl`（Galil=210）；`0x1013E8B8` → `models/w_m3.mdl`（M3=220）；
  `0x1013EA34` → `models/w_mac10.mdl`（MAC10=230）；`0x1013E5C0` → `models/w_p228.mdl`（P228=250）；
  `0x1013E73C` → `models/w_mp5.mdl`（MP5=250）；`0x1013DB58` → `models/w_ump45.mdl`（UMP45=250）；
  `0x1013D6E0` → `models/w_m4a1.mdl` + `weapons/m4a1-1.wav`（M4A1=240）。
- 反汇编脚本：`.ai-tmp/test/feel/{spd.py,mapms.py,pre.py,verify.py}`。

### 二、手枪族：`acc = clamp(acc − K1 × (K2 − dt), lo, hi)`（`dt` = 距上一次开火的秒数）

原版形态（`CDEAGLE` 手写确证，同型见其余 5 把）：
```
fld [this+0x100]                 ; m_iShotsFired
inc …; cmp …,1; jg <尾>          ; 只有"本梭第一发"这条路径才动 acc
fld [this+0xFC]                  ; 上一次开火时刻；== 0（从未开火）⇒ 整段跳过
fld gpGlobals->time; fsub …      ; dt = now − 上一次开火
fsubr <K2>; fmul <K1>; fsubr [this+0xF8]   ; acc −= K1 × (K2 − dt)
fld <hi>;  fcom; … ⇒ acc = min(acc, hi)
fld <lo>;  fcom; … ⇒ acc = max(acc, lo)
```

| 武器 | K1（`fmul`） | K2（`fsubr`） | lo | hi = 复位值 | 证据 |
|---|---|---|---|---|---|
| Deagle | 0.35 | 0.4 | 0.55 | 0.9 | `0x100D6C18`；`0x10141AB0`/`0x10141AC0`/`0x10141AD8`/`0x10141BC8` |
| Elite | 0.275 | 0.325 | 0.55 | 0.88 | `0x100D755D`；`hi 0.88@0x10141BA4` |
| FiveSeven | 0.25 | 0.275 | 0.725 | 0.92 | `0x100D8948`；`lo 0.725@0x10141B18` `hi 0.92@0x10141BD8` |
| Glock18 | 0.275 | 0.325 | 0.6 | 0.9 | `0x100DB299` |
| P228 | 0.3 | 0.325 | 0.6 | 0.9 | `0x100E0B98` |
| USP | 0.275 | 0.3 | 0.6 | 0.92 | `0x100E56B8` |

> `dt` 越大 acc 越大（越准）：快速连发（`dt ≈ 0.15s < K2`）⇒ `acc` 被压低 ⇒ `(1 − acc)` 变大 ⇒ 更散；
> 停火 `dt > K2` 后回升，被 `hi` 钳住。复位值 = `hi`（Spawn / Reset / Deploy 三处槽写的那个常量）。

### 三、复位规则（`tools/probes/feel-acc-owner.py` 逐槽扫 `+0xF8`/`+0x100`）

每把武器的 vtable 里有**三处**槽函数同时写 `[this+0xF8] = 复位值` 与 `[this+0x100] = 0`
（AK47：`slot[0] 0x100D3D44/0x100D3D5A`、`slot[64] 0x100D3EE3/0x100D3EE9`、
`slot[89] 0x100D44B7/0x100D44BD`）⇒ 精度与发数在 **Spawn / Reset / Deploy** 归位。

⚠️ **全 `.text`（361,559 条指令）扫描没有找到 `m_iShotsFired` 的递减点**：
对 `[reg+0x100]` 的写只有①开火函数里的 `inc` / `+1`，②上述三处槽的 `mov …,0`。
⇒ **本片按"只在归位时清零"落**（`CsInventory.ResetAccuracy` 挂到切枪 / 换弹 / 卸装三处）。
不排除经 `lea` 指针间接递减的写法（同类写法在 `0x100CA550` 出现过），故此处标"未取到递减路径"。

### 五、工程接线（差异 #94 收口）

- 数据：`Core/CsWeapons.cs` 的 `CsWeaponDef.Acc*` 字段 + `ApplyAccuracyValues()`；公式

  / `ResetAccuracy`。
- 状态：`CsActor.Accuracy` / `AccuracyShots` / `LastAttackTime`（原版挂在**武器对象**上，

- 消费点：① 模拟侧 `Module/Match/CsInventory.cs` 的 `FireGun`（机器人 / 权威射线）；

## 5.14b 冲锋枪族 5 把散布落值（差异 #94 第四次推进）—— 解开 §5.12 的"两站点窗口重叠"之谜

**结论：那"2 个站点"不是窗口重叠，是原版冲锋枪族只分两档**（空中 / 地面），函数里**没有与 140 的比较**。
锚点 = `CMAC10` 全量反汇编（`slot[87]` = `0x100DF8D0`）：
```
0x100DF8DC  test dword ptr [eax+0x1A4], 0x200   ; FL_ONGROUND
0x100DF8E6  jne  0x100DF8FD
0x100DF8E8  fld  dword ptr [ecx+0xF8]           ; acc
0x100DF8EE  fmul dword ptr [0x10141AB8]         ; ×0.375        → 空中档
0x100DF8FD  fld  dword ptr [ecx+0xF8]
0x100DF903  fmul qword ptr [0x10141CD0]         ; ×0.03         → 地面档
```
⇒ 公式形态 = `Mul × acc`、**无加数**、**无移动档**（`SpreadMoveMul` = 0）。

| 武器 | 空中 mul | 地面 mul | 站点 VA | 档数 |
|---|---|---|---|---|
| MAC10 | 0.375 | 0.03 | `0x100DF8F7` / `0x100DF90C` | 2（手写确证） |
| MP5 | 0.2 | 0.04 | `0x100E01A7` / `0x100E01B6` | 2 |
| TMP | 0.25 | 0.03 | `0x100E4267` / `0x100E427C` | 2 |
| UMP45 | 0.24 | 0.04 | `0x100E4AF7` / `0x100E4B06` | 2 |
| P90 | 0.3 | 移动 0.115 / 静止 0.045 | `0x100E1317` / `0x100E1356` / `0x100E1368` | 3（含 140 比较） |

**代码侧配套**：`CsWeapons.SpreadCoefficient` 的移动档加一条 `def.SpreadMoveMul > 0f` 守卫
—— 否则"地面 + 移动"会落到 `Add + 0 × acc` = 0（散布为 0 的错值）；加数恒 0 的那 5 把因此安全回落地面档。

**⚠️ 一个仍未消除的退化（不是本片的错，登记备查）**：`MP5` / `UMP45` 的 `AccReset` = **0**
（原版 `Spawn` 就是 `fldz` 写 0），而 `SpreadFor` 用「静止站 · `AccReset`」当参考态算比值 ⇒ 参考态系数 = 0
⇒ 这两把**仍走旧回落模型**（`reference <= 0` 分支）。TMP(0.2) / MAC10(0.15) / P90(0.2) 复位值非 0 ⇒ 真正走原版公式。
要收口这两把，得改参考态口径（例如改用 `AccBase + 1/AccDiv` 的"首发后"值），**属 acc 侧口径，本片不动**。
